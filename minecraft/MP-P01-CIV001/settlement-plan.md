# MP-P01｜三域联盟整体人文空间方案 r1

**规划提案，等待 GPT + Owner 审核。** `POLITY_TERRITORY`；本轮交接状态 `HANDOFF_READY` 指国家尺度到区域 Planner，不表示任何建筑可直接施工。`world reads = 0 / world writes = 0`，读取的是已接受的世界调查快照。

方案采用**政治中心、人口市场中心、货物转换中心相互分离，山地地方服务多点化**的骨架。联盟不是三座等大的城，也不是一条从西到东串起全部活动的大道。西岛维持连续生产腹地；内湾提供待核实的跨水交换机会；东岛低地与山坡的转换提高中域服务价值；高山脊使东域保持分段联系和地方自给。共同议事必须可达，但没有理由强迫所有矿石、牲畜和粮食穿过联盟公地。

## 2. Territorial Premise

居民以家庭和地方共同体持续生活，而非为几座纪念建筑服务。西域的低地降低日常生产与短途搬运成本，支持相对多的常住家庭；东域在已批准矿业方向下需要地方生活、粮食补给、燃料维护和矿工安全，但矿口/规模未知，因此先保留**服务网络**，不建虚构矿城。中域的需求来自两个运输方式的等待、损耗与交易，不来自“中间必须有港口”的图面均衡。

联盟层承担共同争端、外交与公共工程；土地、地方治理、武装和生产组织仍主要在地方。由此政治中心可以低常住、高事件峰值，经济集散与多数家庭生活留在不同节点。外部联系只保留“可能的近岸/外海交换”，不指定未知敌国、航路和出口市场。中等宗教强度支持地方仪式与联盟誓约，不要求全国神庙网。专业魔法可改善安全和工艺，不降低粮、水、坡度与维护成本到零。

成熟度暂定为稳定但仍渐进发展的联盟；这是规划假设。低交换分支下，许多服务只是家庭／共有空间中的周期活动，不意味着九座永久城市。

## 3. 地形如何改变方案

西岛陆路绕 C 形弧岸行走：北弧住民不必每日到南部中心，故保留北弧次级集市。南部腹地市场与内湾换载点分工，前者服务常住与生产，后者服务季节性高吞吐。

东岛山地主脊并不适合用一条视觉直线联系各点。候选路径在8格地表采样上绕避水面与陡变，加入标高变化和坡度成本。路段坡比超过0.75的采样边直接排除；这个阈值只是排除粗大陡变，**不是驮运或车辆可行标准**。路线保留完整采样链供下一层重查。

重货最在意累计升降、换载和维护；应尽可能在资源附近分选减重，成品比原矿更适合跨域运送。日常步行需要较近的服务点，不能让远端家庭每天翻山。议事代表的低量流可以承担与高量粮运不同的等待和路线；因此 ROUTE-03 的议事渡运与 ROUTE-09 的商业直达分流。

最大采样坡比：西域两段0.12，公地到转换点0.25；上山段0.53，深山支线可达0.75。后者只能作为驮运走廊搜索证据，未验证实体、净空、转折或连续坡道，不能交给 Builder 当道路蓝图。东南点间路线长度约1,284格，也不能换算成未经校准的“几分钟服务圈”。

水文明确 `flow_and_navigation=unknown`；有水面拓扑不代表能建港。洪水/潮位、地下水、风向、供水与林料产量都没有在本轮被观测，因此只提出供水先行、清污分离和岸端比选，不画虚构洪泛线／林业产量圈。西岛低平也不自动等于肥沃农田。

## 4. 社会需求、流量和外部性

`demand-matrix.json` 的8项需求记录了使用者、频率、等级、空间依赖与可能响应；`flows-externalities.json` 是对应流模型。

三条主要因果链：

1. **生产腹地的季节丰余 + 山地专业人口补给 → 粮食和维护品集散 → 01/02服务日常，03/05承担批量候渡/换载**。规模不足时共享储备与交易可嵌入既有家庭或共同体，不配置一整套独立建筑。
2. **矿业分选、燃料与污染成本 → 资源附近减重、清水和居住保护 → 多个山地服务单元，而非把全部冶炼集中在人口最密的公地或西域**。具体矿口仍未定，烟尘/废水控制要等坡面、水系和工艺证据，不能机械设“下风工业区”。
3. **三席共同治理 + 地方自治 → 公正而独立的议事到达 → Commons是制度稳定锚点，不是所有道路和货物的终点**。交易可以绕过公地，议事不可被商栈货场封堵。

牲畜、候渡旅人和货物可共享区域到达方向，但活动峰值不能互相吞占；后续聚落层解决共享／分时／分离接口。清水、污染物流、燃料更新和山坡维护是国家层必须传下去的关系，不是本轮的建筑间距。

沿海/山地外缘不是已知战争前线。保留地方监视和通行维护的可能需求，不把每座山峰变成堡垒，也不锁不存在的神山。实际外敌或宗教地点获批后，再改变战略层级。

## 6. 锚点与开放空间

低地生活/生产和地方共同体构成 origin anchors；转换交易构成 growth anchors；Commons制度为 stabilizing anchor。每个节点的 why、吸引／排斥、时期、形态后果与移除影响在 `planning-objects.json` 中保存。

开放地不是建筑剩余：西域连续生产地由地方权利者使用，因生计不能被市场扩张无条件吃掉；山地水源、坡面与燃料更新空间由地方管理关系承接，因长期补给而保留；Commons是共同主权面域，不允许缩成小园区，也不等于要全部建满。本轮没有权力划定具体农田和水源保护线。

密度在角色间分化：01可有较连续的混合活动核心，但腹地分散；03/05在换载、共享服务附近集中而不是全地均匀覆盖；06/07/08随台地断续，多点生活不被强迫合并；04的活动峰值不推导出全境最高居住密度。扩张首先解决现有关系的缺口和供水能力，再谈新增节点。

District/parcel/frontage在L0不定几何。传给下游的是形成机制：先有地方土地和接入权，再有交易竞争与分割；家族/庄园/共有制度的差异保留到区域层。禁止从国家级颜色块自动生成统一宅地网格。

## 7. 假设性生长与历史独立性

`growth-sequence.json` 的四阶段均为 **PLANNING_ASSUMPTION**，不是获批历史年表。

1. 地方分散生活与周期会聚可独立持续；山地此时只有低强度混合生计，不先出现依赖未来粮运的巨大矿城。
2. 双边交换支持换载和共享服务；旧到达习惯与土地关系产生搬迁成本，即使没有联盟也能运作。
3. 共同制度为议事到达增加分支，而不是抹掉既有商业流；Commons不能被单域吸收。
4. 远端资源、供水、货量与道路证据满足后才升级07/08/09；条件失败就保持季节节点。衰退时先减专业规模，保留地方生活与必要维护，不为地图好看强保大港。

**Minecraft实施顺序不同**：先审核→更新跨域接口证据→分别下钻区域系统→聚落与必要街区／组团→具体Builder包与另行施工授权。不是按虚构历史顺序把全国先铺一遍。

## 8. 分支与尚未解决的高影响问题

- **运输A**：近岸可航、岸端可用且有持续货量，维持商业与议事分流，南岸参与批量外运比选。
- **运输B**：只能季节通行或南岸不可用，09不升级常年中心，远端降低专业人口和运输承诺。国家网络仍依赖地方互助与有限分批交换，不假装有全年畅通重货线。
- **淡水A/B**：供水足以产生低地丰余则保留较强粮食节点；严重不足则改为低密生产/牧用与有限市场，远端专业规模同步缩小。不能单凭平地在JSON里创造粮食产量。

具体矿种、矿口、水源、外部伙伴、人口、地权细则和航行能力保持TBD。不影响保存一个条件明确的国家层方案；但禁止据本包直接定厂址或开工。若这些证据改变岛间关系或使主链无法成立，回退受影响 Premise/Morphology，而非以装饰细节掩盖。

## 9. 下游接口

`building-program.json` 是区域服务能力要求，不是数量清单；三份 `implementation-packages.json` 交给下一层 **REGIONAL_SYSTEM Planner**。它们有why、保护关系、program、依赖、未决事项和冲突处理。Builder保留 exact footprint、Plan/Section、结构、屋顶、立面、开口、方块和具体地形实现权。

Kit为 `HYPOTHESIS`：支持平地混合生产、岸陆/坡麓换载、台地与维护通路、公共与货运接口区分，并允许地权、年龄、规模和地形改变形态。不引用已完成Architecture Design，不将任何整栋资产复制为全国模板。

`direct_builder_ready=false` 是刻意保持的尺度边界。当前HANDOFF_READY只指L0→L1交接完整；下层必须生成真实场地和更细包。固定条件冲突时返回 `UPSTREAM_PLANNING_ISSUE`，列明证据、相冲突关系和最小需修订对象，不擅自吞公地、封路或移主节点。
