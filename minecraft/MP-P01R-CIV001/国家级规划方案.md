## 2. Premise 与规划上下文

`Fabric Observation = EXISTING_FABRIC_UNVERIFIED`；`Evolution Logic = EXISTING_EVOLUTION`。成熟的松散联盟是工作假设，并不为其指定几百年历史。以下是对这种组织如何成立的因果重构，不是已调查旧城史。下层必须先调查实存和权属，不能按本图清空重建。

- **使用者与生计**：低岛农牧与手工共同体、旅商、山地生产者、氏族／地方权力、三席代表。主要经济互补来自 Canon，具体数量未知。
- **外部关系**：本轮调查窗口之外的邻国、港口、市场和进口量未知。对外交通保留岸线调查需求，不凭空画通往地图外大市场的繁荣主轴。
- **权力与土地**：地方管理普通土地、继承、司法和生产；只有公地明确共同所有。私人家族地块和共同体用地并存是可讨论假设，不冻结详细土地制度。
- **安全**：共同处理对外事务是 Canon；存在具体敌国、入侵方向或战争规模不是事实。这里只提出保通、分散缓冲、共享警报的需求，不设无依据的国境长城。
- **技术**：成熟前现代工程可以降低局部地形代价，不能消除山地重货成本；专业魔法不能替代普通供给链。
- **持续存在的理由**：地方可独立维持基础生计，反复交换才强化区域节点；共同协调降低跨域争端和工程成本。没有未来巨型首都也能运作。

Premise Gate：按当前尺度，人口／资源的精确值以宽区间和分支保留，地理与制度足以提出可被推翻的关系提案。进入 Morphology；不视为人口、供给或场地可建性验证。

## 3. 地形怎样改变关系

西岛 575,363 格²，中位 Y66、最高 Y79；既有调查低起伏平地比例约 67.65%。东岛 1,674,373 格²，中位 Y149、最高 Y300；对应比例约 5.99%。这不是“面积大的岛必有最大城市”：低坡连续性不同，能承担的活动成本也不同。

西岛的 C 形使南北沿陆通行必须绕湾，岛内收集线 R01 因而走西侧连续陆地。它的概念采样全部在陆地，Y62–71；仍未证明道路净空和实存权属。北臂收集点减少末端所有产品每日远送主市场的压力，但不排斥多方地方交易。

中域节点选在北西侧低地搜索，**不是预设天然港口**。这里存在低地到山体的转换，同时接近公地 connector；驻留与分段储运有因果理由。初始代表位置靠近岸缘，制图自检后向同一搜索逻辑内稍移到 (350,1600)，Y66。搜索窗中水面与坡面仍不能作为仓场容量。

北山和东南节点的搜索窗分别有约 3 万与 1.2 万个 `slope8≤0.125` 的陆地柱。这只是碎片化低坡候选，**不能相加即称连续可建台地**。东南搜索窗高程分位约 Y143/202/253，资源点和供水未定位，因此只能是条件分支。重矿石应比较近源减量和搬运燃料两种成本；没有矿种、用水和燃料证据，不能先固定“全部上山冶炼”或“全部下山冶炼”。

水域图色只表示陆水成员；没有潮汐、流向、季节风浪、饮用水量或洪水模型。林地与燃料更新未被定量证明，低地也未被自动认作耕地。需要保留潜在水源保护、海岸缓冲、燃料恢复、地方公共地，而非把未建区域当剩余土地。

## 4. 需求、流与外部影响

完整字段见 `demand-model.json`，每项含 driver、users、magnitude、frequency、maturity、dependencies、externalities 与 response。主要关系如下：

| 需求及原因 | 空间后果 | 下层要验证 |
|---|---|---|
| 季节盈余与分散日常生计 | 主市场承接跨共同体交换，地方保留日常服务和储粮 | 农地、产量、既有人口；不要让生活都依赖远途 |
| 水陆及坡麓载运转换 | 两端集货、缓冲与维修；居民和商旅可混合 | 渡点、装卸、水源、停航期间容量 |
| 山地资源需食物、燃料和劳动 | 就近共同体、可变加工链、分段运输 | 资源真的在哪里；饮水和烟火／废物怎样隔离 |
| 共同治理与争端调解 | 公地作为公共终点，低常住／高会期使用 | 三方可达与峰值；不能让一域垄断访问 |
| 航渡、矿业和供给风险 | 分散储备与局部自理；不把全联盟押在一个端点 | 可用备用方式和损耗，不把图上第二条线当冗余已证 |
| 地方祭祀、照护、普通司法 | 随地方生活嵌入服务，适度联盟公共仪式 | 不机械逐镇配一套独立公共建筑 |

粮食／工具／山地产品双向交换强于公地重货需求。山地原料减少无效运重是方向，不虚构吨位；长期路线频率仅为日常、周期、季节或事件级。货运、牲畜、火源靠近交换同时需要避免侵占安静生活和公共访问。污染排放必须与取水分离，风向和水流未知时不能写死“东侧下风工业区”。

中域并非现代纯物流区，东域并非全域工业用地，西域并非只产粮：地方日常生产与混合服务仍然存在。三域角色是互补优势，不是排他 zoning。

## 5. Anchor、生长与制度空地

每个节点的 Anchor 记录见 `planning-objects.json`，包括时间角色、吸引／排斥、形态后果与移除影响。

1. **G1 地方形成**：持续生计和小规模资源使用 → 分散共同体与可用路／地权 → 已有权利形成惯性 → 季节盈余交换。后续联盟从未出现，这一阶段仍可自理。N02/N05 是角色重构，不断言现在那里存在古聚落。
2. **G2 交换强化**：多次跨水及上山损耗 → N01/N04 等节点逐步集聚，R01/R04/R05 强化 → 载运与岸线控制限制位置 → 需要处理共同工程和争端。没有议会也能通过地方契约交换。
3. **G3 联盟稳定**：跨域事务超过双边安排 → 已批准公地承接共同政治活动，R02/R03 加强 → 共同地权与地方 connector 成为后续约束 → 维护公平访问。无远端扩张仍能工作。
4. **G4 条件扩展／收缩**：只有资源、供水和运路已证明 → N06 及支线可能强化 → 长补给和燃料压力上升 → 必须容许季节化、撤销或改线。不是必须到来的最后阶段。

没有虚构具体旧城墙、旧道、墓地、火灾或年代。下层找到真正遗存后，按活跃继承、残留、可改或受保护身份修订；不能为了匹配这条逻辑历史覆盖实存。

**公地不是空白建设地。** 在本 R1 快照，用东岛自然成员与 X≤88 重现面积 92,124 格²，和 Canon 一致。活动核心只估 10–20 千格²，其中包括内部公共空间；剩余 72,124–82,124 格²仍然是联盟共同土地，不因此改属中域，也不预定每一格用途。整体要承接公共岸缘、开放活动、通达、景观和下层证明的保护需要。X89 是政治界面，不是挖断要求。

其它生产地／水源／林地的留白是有条件的保护与使用关系：地方共同体控制日常使用，污染与过度建成会损害其持续收益，因此不能被城市面积无条件吞并。其精确边界由 L1 的实际土地与自然调查形成。

**全部容量 LOW。** 没有人口调查和下层实存证据，不能用“设计者很确信”提高置信度。搜索方框允许含水和坡面；它只是下一层找地范围。图 03 的内圆与外环按面积和实际地图比例绘制，不能直接将圆覆盖地表当建设边界。东域实际面积应分散到多个台地，而非砍平一个圆。

规模不是从节点称号直接分配。`settlement-capacity.json` 记录了可复算的压力模型：

> 假设户压力 × 含日常院落／通行的户均土地 allowance ＋ 不重复计入的区域服务地 → 向外取整的建成区间。

例如 N01 90–140 户压力、每户 150–190 格²、区域共享 6,000–11,000 格²，原始计算为 19,500–37,600，表达为 20–38 千格²；N03 只有 20–40 户压力，但公共峰值地占比更高；N04 更紧凑同时需要额外转运地。数值是为 Minecraft 场景提出的规模假设，**不是户数 Canon，不指定真实地块面积，也不隐含固定楼层**。

六节点条件启动后的总量 56–115 千格²；不启动 N06 则 53–106 千格²。另给西域分散日常居住总量 6–14 千格²的假设，不预先画几个等距村庄。西域 N01+N02+分散居住为 31–62 千格²，约占西岛 5.4–10.8%，尚余 513,363–544,363 格²。**余地不全是农田，更不证明粮食自给。**

这里有关键供给分支：若西岛实际可生产地和岛内其它生计不能支撑这些户压力，必须降低聚集容量或取得可靠外部交换证据。不能默许地图外无限粮食，也不能以游戏作物机制自动证明历史供给。L1 需要土地可用性、饮水、实际用户／人口尺度与生产系统后，才收敛数值。可以保留更小、周期型的节点而保持互补制度；不必保全每一个面积区间。

## 7. 通道、腹地与分支

`planning-objects.json` 的每条通道有概念中心线、调查半宽、flow、frequency、magnitude、来源、采样见证和 UNVERIFIED_USABLE_ROUTE。地图线是关系方向，不是已设计路基。

- R01 沿西侧连续陆地联系北臂与主市场，途经地方生产，是多项低量流叠加的骨架。
- R02 西域到公地，需跨水，主要为公共访问；未验证渡点或桥位。
- R03 公地经 connector 到中域，政治边界不阻断使用；概念采样仍有局部水柱，L1 必须寻路或解决局部跨越。
- R04 北侧跨水是主货流候选。若北侧条件不成立，L1 比较其它岸段的成对渡运，不能把失败码头留着只改名字。N02 的地方收集角色可保留，转运容量须撤减。
- R05 从低地到北山，重货成本推动分段运输。Y 与局部水段足以反对“平地直路”假设，不足以证明最佳山口。
- R06 初步概念采样 1,285 点中含 187 水点，陆段 Y62–201。已拒绝把它叫已通纯陆运干线。L1 比较绕行、分段岸运或根本不启动远端活动；都不成立则 N06=0，主联盟链仍成立。

## 8. Program 与 Architecture Kit 接口

本轮 Program 是功能负担，不是建筑配额。`building-program.json` 将每项需求连接到空间服务、量级、邻接、共享可能、成熟度和外部影响。没有单体 footprint、屋顶、柱距、门窗、街巷尺度或 palette。

下一层 Kit 需支持的能力：西域地方居住与农牧／存储院落互嵌、生产车畜服务；中域混合商旅／住居／短储运与岸陆高差接续；东域不同台地分散、垂直交通与防火／排水／生产服务；联盟公共空间容纳低日常和高活动峰值。共同 DNA 来自 Canon 的地方自治、务实协商与石木技术，不从未读取的后续建筑方案导入。

差异可随财富、活动、地形、继承与修补改变。Kit 不得提供整栋重复复制作为唯一答案；具体建筑由以后 Builder 保有作者权。本轮不下钻 parcel，不把“连续 frontage”变成冻结街线。

## 9. 四个 L1 交接包

完整合同在 `implementation-packages.json`，recipient 全部是 `minecraft-planner / REGIONAL_SYSTEM`，不是 Builder。每包含 scope/search refs、原因、anchors/flows、UPSTREAM_FIXED、DOWNSTREAM_TO_RESOLVE、DOWNSTREAM_ADAPTABLE、三分容量、跨包依赖、REVISION_TRIGGER 和期望图／数据。

1. PACKAGE-01 西域生产—市场系统：校准生产供给、人口压力、地方服务与北渡关系。
2. PACKAGE-02 中域与跨水接口：优先核实两端接驳、岸陆关系、connector 和上山链。
3. PACKAGE-03 东域共同体：先找资源、水源、燃料和可用台地，再决定条件节点及分段运输。
4. PACKAGE-04 公地与三域访问：守住整个 Canon 公地，验证公共访问与峰值，不下钻议会建筑。

Canon／Owner 固定约束现在有效；本轮设计关系的 fixed 身份只有在父案被接受后才适用于 child。一个规划文件被写出不等于上层已经批准。

下层可以移动候选、拆合低层节点、改变可替代路线、收敛面积；不能偷偷改变三域互补、公地归属或以单个矿都取代多个地方共同体。若局部适配仍无解，报告 `UPSTREAM_PLANNING_ISSUE`，最小化修订相关节点／流／容量，父案增加 revision，关联 child 标记 stale，重新运行相关 Gates。

**项目实施顺序不是历史顺序**：先 GPT + Owner 审核本案 → 同步 L1 跨水及供给调查 → 各区容量收敛和 L2 包 → 逐级到 L4 后再交 Builder。没有施工顺序或世界写入授权。本任务到此停止。
