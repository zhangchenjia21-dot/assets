这是可交下一层 Planner 继续调查的区域提案，不是已接受 Canon、实地建设许可或回归结论。`world writes = 0`。父包为 MP-P01R r1 PACKAGE-03；没有读取 MP-P02 的方案、Critic、图或审核，也没有读取其他后续东域规划答案。

## 1. Premise 与权限

东域的存在理由是矿产总体丰富的山地与多个自治共同体之间的长期联系；稳定生活还需要饮水、食物、普通工程与可负担的运输。前者来自已批准 Canon，具体矿脉、生产点、产量和供水不在证据中。不能把地图中的岩面直接变成矿镇。

规划采用北部两个协作支点和南部条件分支。北岩台承担可共享的交割、储备、维修；西肩候选保留更多家庭生活与地方共同体功能。南部只有在真实生产、供水和交通成立后才启动，岩面混合地与较高草土地互为替代。它们不是四座必须建设的新城。

用户、社会需求：地方家庭、山地工匠、间歇性驮队、季节驻留者与共同体代表。强地方自治、东席联合代表多个共同体、成熟前现代石木技术与低普及魔法是 Canon。家庭用地尺度、交换频率、共同储备和轮换协商的具体空间方式均为本轮假设。假设地方利用权先于区域总图，具体所有权仍需核查。未发现支持区域战争前线的证据，因此不设置要塞链；安全需求限于货物、路径、火与污染风险，不创作战争史。

`EXISTING_FABRIC_UNVERIFIED` 与 `EXISTING_EVOLUTION` 同时成立。没有检查当前建筑/道路，不能称空白，更不能清空既有建设。以下历史链是因果模型，不是宣称观察到古道或废址。

## 4. 需求、流与外部性

完整字段在 planning-data.json 的 demands：包含用户、量级、频率、成熟阶段、依赖与空间响应。北部30–60户是父包压力，不是人口计数；没有已知吨位或日供水量，不能计算伪精确运输运力。

1. 每日家庭生活 → 饮水、口粮、维修、卫生必须相互兼容 → 先证明生活支点，再容纳交割。共享储备可以与家庭/工艺活动嵌合，不直接要求独立粮仓建筑。
2. 西域产品经中域上山、山地产品下行 → 北部优先提供周期交割与修理 → 装卸与居民通行需分流，节点规模不按行政等级单排。
3. 多个自治共同体联合 → 周期协商、互助与履约 → 保留多个日常生活中心，不设唯一行政矿都。
4. 若资源支持增长 → 工具、口粮和燃料反复进入远端 → 先季节补给，再评估常住；不能只算矿石出山，忽略空返和输入。
5. 高扰动生产 → 烟、火、污水与运输冲突 → 本轮只保留生产支持关系；重冶炼的水流、风与燃料没有证据，不指定一个“工业区”。污染与居民饮水必须在下一尺度分开验证。

食物敏感性：暂按当地稳定农产为0的保守供给情景检验依赖；并非断言不能种植。若下游证实生产土层与水，则减少输入压力，不能自动增加户数。木料敏感性同理：植被不抵扣供应责任。专业魔法不用于跳过水、粮、道路。

## 5. Anchor、历史链与反事实

ORIGIN 是经证实的水与生计，而不是某个预先画好的中心点；目前它还没有坐标。GROWTH 是降低重复转运损耗的共享交割；STABILIZING 是共同体履约与东席联合；南部新增生产是可删除的条件增长Anchor。

历史假说分四步，各自可独立停留：

- 地方生活在真实水与生计附近延续 → 既有权属/路径成为约束 → 才可能产生剩余交换。
- 交换变频繁 → 在已有通达与可用服务面嵌入维修/交割 → 通行和土面保留限制后续扩张。
- 互助与协商稳定 → 多个地方中心共用服务 → 稳定北部网络可永久不向南扩张。
- 远端生产若被确认 → 季节驻留起步 → 供给成功才增加常住；衰退则退出，保留恢复责任。

这不是Minecraft施工顺序。若未来南部从未出现，前三级仍有生活和交换理由；若北部缺少可维持生计，第一阶段也不能成立，需回到SCOPED/PREMISE调查，而不是借未来矿业自圆其说。

## 6. 交通、层级与腹地

ROUTE-01连接父包中域接口与北岩台；ROUTE-02连接北部两个搜索对象；ROUTE-03/04是互斥的远端交换分支。图线只有关系转折点，不是选定路线。关系线探针显示其所穿地形，不论视觉连续与否，均不证明驮运、坡度、净空、桥渡或全天候可用。

顺序应是验证交换双方压力 → 调查可接受绕行/分段储备 → 比较定址，不是把画好的直线改成一条道路。候选间距来自所选地表和相互服务需求，不是等距布点，也不设置没有水/需求依据的中途驿站。若远端全程负担不能维持，应季节化、减量或删除，而不是添一串服务节点掩盖成本。

北岩台的吞吐重要性可能高于常住人口；西肩在日常生活与地方组织上较重要；南部没有预设政治等级。Catchment是“地方家庭—共享交割—中域接口”和“经证实远端生产—补给节点”的关系，不能据图框圈成矿权或行政边界。Commons既包括受地方协议控制的临时卸载空间，也包括权属待查的土面和植被斑块；谁使用、何时使用、为什么不建见SPACE对象。未定坐标的饮水缓冲不画成伪精确保护圈。

形态约束止于区域层：北部生活与服务分簇但交织，禁止连续填平连接为单一平台；南部保持条件性小簇，不把整个高地划为生产镇。街区、地块、准确密度和前沿均交SETTLEMENT，不画门窗与栋数。

## 8. Program、Kit与交接

PROGRAM从生活、交换、协商、资源支持和地表延续五项需求导出，允许共享/嵌入空间。Kit只要求混合生活工作、驮运/服务接口、可撤回驻留、地表差异适应和多共同体共同语言；禁止整栋复制、统一石台、固定屋顶和palette。

三个SETTLEMENT交接包：PACKAGE-01北岩台、PACKAGE-02西肩、PACKAGE-03南部互斥候选系统。每包明确fixed、待查、可调整、容量、地表要求、跨包关系和revision机制。先做01/02的联合现状—供水—运输调查，确认北部整体可维持，再做南部条件调查。之后分别形成聚落规划及L3交接，不直接给Builder。

本案关系只有在被接受后成为下游规划约束；Canon和Owner禁令立即有效。新证据与关系冲突时先局部调整位置/分簇/容量/季节性；无解时指出最小受影响node、route、capacity并提UPSTREAM_PLANNING_ISSUE。不得覆盖父案或顺手设计中域。
