## 2. Owner-approved land rule

正确政治土地模型：

```text
Alliance Commons
= Candidate A 主体全部陆地
− 东侧连接主岛的陆颈 / 连接带

Middle Domain
= 该东侧连接带
+ 向右继续进入东岛西部低地 / 坡麓
```

去掉东侧连接带后，A 的剩余主体在玩家视觉上本身就是近似椭圆 / 卵形的“中心岛”。

**不得在 A 主体内再人为套一个更小的椭圆公地区。**

## 3. Superseded capacity numbers

以下此前规划数字全部撤回，不再作为设计基线：

- Political Precinct `22,000–32,000 blocks²`；
- Alliance Commons `55,000–65,000 blocks²`；
- built footprint `14,000–20,000 blocks²`；
- Council Hall `3,000–5,000 blocks²`；
- 任何人为预设的椭圆长短轴数字。

原因：这些数字都不是基于 `A - east connector` 的真实政治土地面积推导。

## 4. 下一步必须先做 Boundary Fit

先利用现有 A / parent geometry 找到自然连接带切口，产出：

- east connector cut line / geometry；
- Alliance Commons actual geometry；
- Alliance Commons actual area；
- Commons bounds / major dimensions；
- connector area；
- 一张轻量对比图；
- 若自然切口存在歧义，最多给 2 个候选，不得自行隐藏歧义。

不需要 broad rescan，也不需要 world write。

## 5. Boundary Fit 后再做 Capacity

得到真实 Alliance Commons 面积后，再按：

```text
actual Commons area
+ shoreline / terrain geometry
+ long-term political program
+ open-space needs
+ growth reserve
+ historical public-building scale
+ Minecraft readability
→ mature built footprint
→ Council Hall search range
```

重新推导。

这一次不得先从“想让大厅多大”倒推政治中心面积。

## 6. 长期 Program 仍然保留，但面积待重算

长期政治中心仍可包含：

- 三席议事大厅；
- 三域代表馆 / 驻馆；
- 档案 / 书记 / 裁判功能；
- 联盟誓约 / 神圣仪式空间；
- 外交 / 公共接待；
- 警卫 / 后勤 / 储藏；
- 公共前场、院落、短街、路径、岸线空间、结构性植被与后续扩建余量。

这些功能本身仍有效，但所有 footprint 数字重新开放。

## 7. 小批次施工原则不变

即使最终 Alliance Commons 很大，真实 world-write 仍保持：

> **一个任务只施工一个主要建筑 / 主要空间目标 + 必需最小接口。**

总体规划可以覆盖整个联盟公地，但不能一次性交给 Codex 全部施工。
