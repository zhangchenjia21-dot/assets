# Middle Kit v0.1｜参数与适配契约

## 成熟度与使用

`PROPOSED` 为规则提案；`PREVIEW_VALIDATED` 表示本轮指定参数实例已受有限几何检查，不表示整个范围内所有组合都有效。`BUILT_AND_OWNER_ACCEPTED` 必须后续真实建成、Owner接受后才能设置。本轮没有任何该等级条目。

R01/R02/R04/R06/R10及M02/M03附本轮实例见证；其中门仅为几何开口，楼梯仅为半格实体原型，**真实碰撞与门状态未验证**。其余规则、模块、typology和palette为PROPOSED。模板不是可直接运行的施工指令，也不是正式入库资产。

## Shared DNA 与 Middle 差异

共同CIV DNA是石脚、连续支承的石木构造、按功能分级的开口、克制材料与从长期使用形成的变化。Middle的独特处是地面昂贵、多功能上下叠合、仓门与家门分流、共用院与窄巷，以及从岸/低地到坡麓的转换。West的广域农牧布局、East的强山地工程不能用本版房型直接换色替代。

## 尺度与构造

|系统|v0.1提案范围/规则|重核条件|
|---|---|---|
|独立石脚|局部填0–2、切0–1格；墙柱底连续落地|超过范围或浅层体积外另读证据|
|跨间|3–5格；末跨2–3格可服务交通|跨度、重屋面与柱位变化重核梁架|
|楼层|生活层差4格，仓首层差5格，净高至少2.5|不是将任意新层机械叠上去|
|坡屋顶|双坡1:2或1:1；低尽端可四坡；常用挑檐1格|条带厚度随坡比闭合，屋面不能薄片悬空|
|立面|仓底实墙、生活窗1–2×2；3–5格节奏随结构和房间|楼梯孔/柱脚位置不自动开窗|
|入口|家/店2×3已预览；仓3×3已预览，扩高4为提案|贯穿整墙且接上两侧地坪|
|楼梯|2格宽，层差4/5，跑长随差值4/5；两端≥1格落脚|半格踏步、顶孔、护栏和2格人体净空一起复查|
|檐廊|雨棚深1–2，净高3–4；门廊深2–3；阳台深1–2|后两者不是本轮已建/已验证模式|
|院墙/服务院|低墙1–2格、门2–3格；服务院24–72格|不围死排水，不把货物停在居民通道|
|街边|退界0–2格由门槛/棚/转角需要产生|不默认统一退界或镜像同款|
|边墙|当前独立屋；共墙仅作条件条目|必须另审防火/维修/排水/分户疏散|

模块不因参数合法就自动“设计成立”。尤其拱廊、阳台、院门等尚未在本次组团实例化，不能引用其它模块的检查给自己标记 PREVIEW_VALIDATED。

## 六类骨架

T01商住先定街面买卖与独立家门，再给上层生活；T02短仓先定干燥承重层、卸货与住家分流；T03冷作修理先定作业面和材料/家居距离；T04旅舍先解决共用梯厅、住客与经营家庭的私密界面和备餐烟道；T05消息服务控制为可读的低尺度公共端点；T06共用院组织通行、家务与服务，不能先画一个围墙矩形再贴标签。

每类JSON都给 required_core、optional_modules、dimension_ranges、variation_knobs、terrain_adaptation 和 incompatible。范围是探索带，不是均匀宅地尺寸。两种不同功能不得只从同一个外壳改长宽高，须重新画 Space Graph 和剖面。

## 材料、年代与变化

材料族按石脚/木框/填充/屋面/强调分开。石、木与低饱和土色共享亲缘，旅舍可以更浅的填充表达维护投入，冷作屋可以较实用的填墙。屋面、进口木材、砌块是候选选材，不推导附近已有供应点。预览使用色块近似，不承诺Minecraft真实纹理已验证。

变化以功能、建造阶段、地块边缘、地形、街道角色与维护等级为依据；禁止均匀随机混材、每栋同一破损纹样、按固定间距复制窗/棚/树。新增一项变化应说明它改变了什么活动或构造关系。

## 复用次序

先读取最新世界与accepted边界，形成 Site Context → 用途与空间图 → Plan/Section/Sequence → 选择骨架和模块 → 重新编译几何 → Critic → Preview → GPT/Owner审核。只在新的有界world-write授权中才生成真实blockstate/施工批次。新规则先进入版本化提案，不能因单次模型生成就自动称为成熟地方传统。
