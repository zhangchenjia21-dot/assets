# 大型扫描数据交付与审核契约

状态：**ACTIVE ARCHITECTURE / GOVERNED BY D-010**

适用于 Natural Geography、Regional Reconnaissance、资源 / 可达性调查、build-site high-resolution observation 等可能产生大型机器证据的任务。

## 1. 目标

在不降低调查精度和可验证性的前提下，减少：

- Codex push 体积；
- Git history 膨胀；
- GPT 独立审核传输量；
- revision 对 predecessor raw evidence 的重复提交。

核心原则：

> **高分辨率扫描可以很大，但 GitHub Review Bundle 应该很小。**

---

## 2. 四层交付模型

### L0｜Source of Truth

目标 Minecraft world。

### L1｜Local Raw Cache

完整高分辨率观测与大体积中间层，例如：

- per-column observed SQLite；
- dense NPZ / arrays；
- 完整 raw topology labels；
- 全量 cross-check trace；
- 大型临时 rebuild database。

默认：`LOCAL_ONLY`。

### L2｜GitHub Review Bundle

供 GPT / 后续 Agent 独立审核和继续规划的轻量事实包。

默认进入 GitHub。

### L3｜Human-readable / Canon-facing Views

Markdown 报告、适度地图、结论索引；仍属于 Research，除非经过 Canon Promotion。

---

## 3. 默认 GitHub Review Bundle

建议标准结构：

```text
review/
  index.json
  key-metrics.json
  stratified-witnesses.jsonl
  boundary-witnesses.json
  topology-witnesses.json
  limitations.json
manifest/
  source-fingerprint.json
  raw-cache.json
  lineage.json
validation/
  summary.json
  rebuild.json
profile/
  regional-summary.json
  biome-profile.json
  terrain-profile.json
  vegetation-profile.json
  owner-hypothesis-evaluation.json
  natural-zones.jsonl
reports/
  ...
visual/
  ...
tooling/
  ...
```

实际任务可删减不适用项，但不得削弱以下能力：

1. 知道扫描了什么范围；
2. 知道源世界是哪一个 epoch；
3. 知道结论从哪些数据 / 算法产生；
4. 能复核关键 claim；
5. 能识别 uncertainty；
6. 能在需要时找到 / 重建 local raw cache。

---

## 4. Review Bundle 的证据策略

### 4.1 Key metrics

只保存会被后续推理使用的统计与分布，不复制每个 raw row。

### 4.2 Stratified witnesses

独立 raw cross-check 不需要把数百 / 数千条完整 NBT 展开全部提交。

GitHub 默认保存：

- sampling design；
- category counts；
- PASS / mismatch summary；
- 按关键类别保留代表性 witness；
- mismatch 若存在，全部保留。

完整 cross-check trace 可留 Local Raw Cache。

### 4.3 Components / geometry

不得把所有微小 component 的巨大展开 JSON 当作默认 GitHub 交付。

优先保存：

- major components；
- top-N / threshold-relevant components；
- zone actual geometry；
- aggregate count / area histogram；
- boundary / topology witness；
- 可从 local cache 重建全部 component 的方法。

如果某任务必须让后续 Agent 查询所有 component，则优先使用紧凑的 lightweight SQLite / RLE / compressed geometry，而不是几十万行 pretty JSON。

### 4.4 Maps

地图是阅读层，不是事实源。

- 保持足够判断方向、边界、梯度和候选区域；
- 不追求无必要的超高分辨率；
- 原始 raster / debug image 默认 Local-only。

---

## 5. Lightweight Query Store

GitHub 可以保留一个轻量 query store，但默认不再保存完整 per-column database。

推荐 GitHub query store 包含：

- scope；
- major objects / zones；
- aggregate profiles；
- compact geometry runs；
- key patches；
- evidence references；
- source hashes；
- limitations。

如果精确到任意单柱的查询需要百万级 row：

- 在本机使用 Local Raw Cache；或
- 对当前 world 按需重读；
- 不为了“以后可能查询”默认把整个 observed database push GitHub。

---

## 6. Raw Cache Manifest Contract

GitHub 至少保存：

```json
{
  "cache_id": "...",
  "status": "LOCAL_ONLY",
  "retention": "REGENERABLE | PRESERVE_LOCAL",
  "sha256": "...",
  "bytes": 0,
  "schema": "...",
  "source_world_fingerprint": "...",
  "source_epoch": "...",
  "generated_at": "...",
  "rebuild_command": "...",
  "local_path_hint": null
}
```

`local_path_hint` 可以因机器不同而变化，不得作为跨机器唯一定位方式。

如果 cache 不再存在，必须明确标记 `MISSING_LOCAL_CACHE`；不得假装 GitHub 轻量包仍包含完整 raw evidence。

---

## 7. Revision / Incremental Scan Contract

R1 / R2 等任务：

1. 对 predecessor source hash / epoch 做 freshness audit；
2. 未变化数据复用，不重扫；
3. 变化范围只 refresh delta；
4. Local Raw Cache 可产生统一新版本；
5. GitHub 只保存新 unified review profile + lineage / delta summary；
6. 不复制 predecessor 的大型 raw archive。

---

## 8. Size Budget

默认：

```text
TARGET_GITHUB_DELIVERY <= 15 MiB
REVIEW_REQUIRED_IF > 15 MiB
NO_PUSH_BY_DEFAULT_IF > 25 MiB
```

超过 25 MiB 只有以下情况可例外：

- Task 明确要求某不可重建关键证据必须远程保存；
- GPT / Owner 在执行前或发现后明确授权；
- Completion 写清无法用 Review Bundle / Cold Archive 替代的原因。

压缩不是自动例外理由。

---

## 9. Cold Archive

对于世界已变化、未来无法从当前 world 重建的高价值 raw snapshot：

```text
retention = PRESERVE_LOCAL
```

优先长期保存在本地冷存储。

如需要远程冷备，选择 Git LFS / Release / object storage / 专门 archive，由单独决策授权。

**main Git history 不承担默认 cold archive。**

---

## 10. Independent Review Contract

GPT 独立审核默认不要求下载完整 Local Raw Cache。

审核顺序：

```text
1. commit / task scope
2. scope completion
3. source fingerprint / freshness
4. key methodology / algorithm
5. key metrics
6. stratified raw witnesses
7. topology / boundary witnesses
8. deterministic rebuild
9. lightweight query store
10. maps / report / limitations
```

只有出现异常、矛盾或高风险 finding 时，才要求深入 raw cache 或重新读取 world。

因此：

> **Reviewability ≠ 把所有 raw bytes 放进 GitHub。**

---

## 11. Task Shaping Requirement

以后凡 Task 预计产生大规模扫描数据，Task Packet 必须显式写：

- Local Raw Cache 位置策略；
- GitHub Review Bundle 内容；
- size budget；
- raw-cache manifest；
- predecessor reuse / delta 策略；
- cold-archive 条件；
- 哪些 evidence 是必须 remote、哪些是 local-only。

如果 Task Packet 没写，默认采用本契约。
