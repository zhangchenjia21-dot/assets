# 世界构建原则｜建筑师

## 1. 先读世界，再写世界

存档已有地形是自然地理的硬事实。国家、文明、首都、边界、道路和历史应在理解地形之后形成，而不是先写一套完整世界观再强迫地图适配。

但“先读世界”不等于“所有设定都必须先被存档证明”。本项目的严谨性目标是：**让 Canon 与玩家实际可见的 Minecraft 世界相容，并控制未来落实设定所需的改造成本。**

## 2. 分层，不混淆

```text
Minecraft Natural Geography
→ Regional Reconnaissance
→ Human Geography Hypothesis
→ Owner-approved World Canon
→ Architecture / Settlement Grammar
→ Site-specific Build
```

自然地理调查不能自动生成政治事实；宏观 Atlas 也不能直接承担文明 / 种族落位。

## 3. 证据等级永久保留

- **Observed**：直接读取世界；
- **Observed-by-Owner**：Owner 在真实 Minecraft 世界中的直接实地观察；
- **Derived**：从 Observed 计算；
- **Interpretive**：规划线索与潜力判断；
- **Canon-authored**：Owner / GPT 在与可见世界相容的前提下主动创作、但并非原存档已证明的世界事实；
- **Canon**：Owner 明确批准的世界事实。

Research evidence 与 Canon authority 不能混淆。`Canon-authored` 可以合法进入 World Canon，但不得伪装成 Observed。

## 4. 发现式世界构建

优先采用：

```text
实际地形 / biome / 水系 / 高程 / 可利用空间 / 已验证资源
→ 生计、移动与风险约束
→ 生活方式与聚落逻辑
→ 社会 / 部族 / 文明候选
→ 在环境相容范围内主动补充隐性资源 / 历史 / 制度等 Canon
→ 魔法 / 技术实践
→ 建筑语言
```

山脉、河谷、海峡、群岛、森林、荒地和天然走廊应该能够成为文明形成的原因，而不是文明设定完成后的背景板。

## 5. Regional Reconnaissance Gate

Current Natural Atlas 用于宏观筛选“哪里值得继续看”，不用于直接决定“谁住这里”。

任何文明 / 种族在具体 Minecraft 区域落位前，必须至少完成：

```text
Current Natural Atlas macro query
→ regional in-game / high-resolution reconnaissance
→ regional natural profile
→ terrain / biome / water / elevation / flatland / accessibility evidence
→ civilization / species hypotheses
→ GPT + Owner discussion
→ Owner explicit approval
→ World Canon
```

这个 Gate 主要约束**高可见、难以低成本伪造的环境事实**。它不要求所有地下矿藏、深层地质、隐藏遗迹等隐性设定都先完成全域验证。

## 6. 可见性 / 改造成本原则

受 `D-013_可见世界约束与隐性设定可创作原则.md` 约束。

### 高可见、高改造成本

山脉、海岸线、大河、大型森林 / 雨林、区域整体 biome / 植被气质等，优先服从真实存档。若要改变，必须把实际 terraform / landscape rewrite 当成明确任务。

### 可见但可逐步建设形成

农田、道路、桥梁、码头、矿井入口、采石场、人工林等，可以先作为文明设计，再在真正进入玩家视野时通过 Build 实现。

### 低可见 / 隐性、低冲突成本

地下矿藏总体丰富度、深层矿脉、地下遗迹等，只要不与已知证据明显矛盾，可以主动创作成 Canon，不必先证明原存档已经按该设定生成。

核心原则：

> **Evidence constrains; creation fills.**

既不能无视真实世界，也不能把项目变成“没测到就不能创作”的调查工程。

## 7. Biome 不是文明标签

禁止默认：

- 沙漠 = 沙漠帝国；
- 森林 = 精灵；
- 雪地 = 北境王国；
- 多山 = 矮人 / 矿业文明；
- 热带雨林 = 自然种族。

Biome 只是环境证据的一部分，必须与地形、水系、高程、资源、交通和历史共同解释。

同样禁止反向操作：先决定“这里必须住某个种族”，再挑选几个 biome / 地貌特征为既定结论找理由。

但当文明已经通过 Region-first 流程获得合理空间基础后，可以在不破坏可见世界一致性的前提下主动创作地下资源、历史事件、制度等低冲突事实。

## 8. 区域内部差异优先于整块着色

一个 Atlas region、岛屿或大陆不自动等于一个文明或国家。

在文明设计前，应主动检查区域内部是否存在：

- 高低差；
- 不同 biome / 植被环境；
- 平原、山地、岸线、岛片等空间分异；
- 不同交通条件；
- 足以形成不同部族 / 聚落适应方式的自然分区。

如果存在明显内部差异，优先从这些差异中提出多个生活区 / 部族区 hypotheses，而不是把整个区域涂成一种文化。

## 9. 名称与政治地图后置

GEO / HYD / FEAT / SITE 以及 NGEO / NHYD / NFEAT / NSITE 首先是机器空间 ID。正式地名、文化区、国家边界与行政归属只有在 World Canon 阶段经 Owner 批准后才建立。

## 10. Canon Promotion Gate

重大世界事实默认：

```text
Research / Terrain Evidence
→ Regional Reconnaissance
→ GPT + Owner Discussion
→ Hypothesis / Options
→ Owner explicit approval
→ world/ Promotion
```

Owner 未明确批准时，不得标记为 CANON / DECIDED。

其中隐性、低冲突世界事实可以在 GPT + Owner Discussion 阶段由创作产生，不要求存在对应 Observed 证据，但必须明确标识其来源为 Canon-authored。

## 11. 经验基线

### D-007

南部大岛第一次文明试点证明：只依据宏观 Atlas 把 `NGEO-009` 直接指定为林地长生种文明属于过早 promotion。

因此坚持：

> **先实地考察区域，再让文明从当地自然条件中生长出来。**

### D-013

WB-003R 之后进一步明确：地下富矿等低可见、低冲突设定不需要被原存档预先证明。

因此补充：

> **真实 Minecraft 世界决定创作边界，但不会替代创作本身。**
