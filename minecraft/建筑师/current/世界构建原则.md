# 世界构建原则｜建筑师

## 1. 先读世界，再写世界

存档已有地形是自然地理的硬事实。国家、文明、首都、边界、道路和历史应在理解地形之后形成，而不是先写一套完整世界观再强迫地图适配。

## 2. 分层，不混淆

```text
Minecraft Natural Geography
→ Human Geography Hypothesis
→ Owner-approved World Canon
→ Architecture / Settlement Grammar
→ Site-specific Build
```

自然地理调查不能自动生成政治事实。

## 3. 证据等级永久保留

- **Observed**：直接读取世界；
- **Derived**：从 Observed 计算；
- **Interpretive**：规划线索与潜力判断；
- **Canon**：Owner 明确批准的世界事实。

低一级证据可以启发高一级，但不能静默升级。

## 4. 发现式世界构建

优先采用：

```text
地形 / 水系 / 资源 / 交通约束
→ 生计与经济
→ 聚落与权力中心
→ 冲突与历史
→ 文明 / 国家
→ 建筑语言
```

山脉、河谷、海峡、群岛和天然走廊应该能够成为历史发生的原因。

## 5. Biome 不是文明标签

禁止默认：

- 沙漠 = 沙漠帝国；
- 森林 = 精灵；
- 雪地 = 北境王国。

Biome 只是环境证据的一部分，必须与地形、水系、资源、交通和历史共同解释。

## 6. 名称与政治地图后置

GEO / HYD / FEAT / SITE 首先是机器空间 ID。正式地名、文化区、国家边界与行政归属只有在 World Canon 阶段经 Owner 批准后才建立。

## 7. Canon Promotion Gate

重大世界事实默认：

```text
Research / Terrain Evidence
→ GPT + Owner Discussion
→ Hypothesis / Options
→ Owner explicit approval
→ world/ Promotion
```

Owner 未明确批准时，不得标记为 CANON / DECIDED。
