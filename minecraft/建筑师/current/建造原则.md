# 建造原则｜建筑师

## 1. 单目标高质量

默认一次任务只严谨设计一个主要建筑 / 聚落目标。不要为了“丰富”而在一个任务中同时铺满整片领地。

## 2. 小批次施工

默认：

> **一个 world-write Task = 一个主要建筑 / 一个主要空间目标 + 为其成立所必需的最小接口。**

可以随主体一起处理的内容，只限有限的基座、入口前场、必要台阶 / 接路、挡土墙和紧邻主体的地表 / 结构性植被调整。

不得因为“周边以后也需要”就在同一任务中顺带铺开：

- 多座主要建筑；
- 整片广场或行政区；
- 大范围道路网；
- 大规模码头 / 桥梁系统；
- 成片街区；
- 与当前主体没有直接成立关系的大范围景观重做。

如果一个建筑本身很大，或施工范围明显扩大，必须先解释为何不能进一步拆分；不得把 Site Context / flat patch / survey bounds 自动当作 world-write 范围。

第一批施工通过 Owner in-game review 后，再决定是否进入相邻目标。

## 3. 历史真实性优先于模板化奇幻

历史题材或有现实原型的建筑，先研究真实历史形态、功能、工艺、空间与社会背景，再进行 Minecraft 化和奇幻化，不用现代人的默认规划常识替代历史逻辑。

中世纪 / 前现代聚落默认避免：

- 方正网格道路；
- 规则等宽地块；
- 现代郊区式退界与均匀间距；
- 为视觉整齐而忽略道路生长、地形、教堂 / 市场 / 水源等真实组织因素。

## 4. 地形处理

保留并顺应自然地形骨架，不为方便把大范围地貌粗暴推平。

施工范围内已有草、作物、树木等杂乱植被默认可以清除；建筑主体完成后，植物与景观应按项目风格、空间逻辑和视线重新设计，而不是把原生随机植被机械包进建筑。

## 5. Site-first

具体设计前先理解 SITE：

- 坡度与高差；
- 主要视线；
- 水体；
- 进出路径；
- 周边地貌；
- 可施工尺度；
- 已有人工内容。

粗 Survey 只能用于筛选，不能替代现场复核。

## 6. 设计模式

默认采用约束驱动的单方案设计；重要 / 复杂建筑可以增加 Architect → Critic → Revision。

需要 Owner 对比时再进入多方案 Preview，不把多方案作为每次任务的固定成本。

## 7. World-write Gate

调查、研究、规划和 Preview 默认不得写世界。

实际施工必须由当前任务明确授权范围，并保留可核验的 world-write / undo / completion 证据。
