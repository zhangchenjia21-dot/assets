Owner 在 AB-001P1 的 A / B 消歧后明确选择：

> **A**

因此三席议事大厅第一 Pilot 的当前 Site Anchor 固化为：

- 工作名：**湾内中心低地 / Council Centerland**；
- AB-001P1 Candidate：`A`；

此前 Owner 使用的“西部平岛的中心岛”是视觉/空间指称。后续正式规划不得再把 A 错写为独立岛或 west land component 1。

这次确认只关闭 Site mapping，不等于 world-write authorization。

## 2. First Pilot Scope

第一 Pilot 的主要目标只有：

> **三席议事大厅（Three-seat Council Hall）**

不得因为 Site 是未来联盟政治中心而在同一施工任务中顺带建设：

- 联盟大广场；
- 三域代表馆；
- 档案馆 / 金库 / 裁判庭；
- 完整码头；
- 跨岛桥；
- 道路网；
- 大规模园林；
- 成片城市街区；
- 其它第二主要建筑。

这些可以作为未来空间关系被预留，但必须拆成独立后续任务。

## 3. Bounded Construction Principle

Owner 明确要求：Codex 施工不要一次承担过多建筑或过大范围。

以后本项目默认：

> **一个 world-write Task = 一个主要建筑 / 一个主要空间目标 + 为其成立所必需的最小接口。**

“最小接口”可以包括有限的：

- 建筑基座；
- 入口前场；
- 几格范围的接路 / 台阶；
- 必需挡土墙；
- 紧邻建筑的地表整理与结构性植被调整。

不得把“周边顺便完善”解释成扩大施工范围。

### Size-guard correction

本文件曾预设：

- 主体 footprint `<=45×45`；
- 单方向约 52 格说明门；
- 第一批 intervention envelope `<=64×64`。

Owner 指出这些数字没有先经过“整个 Council Centerland 总容量 / 未来建筑 Program / 三席议事大厅真实功能尺度”的完整推导。

因此上述固定数值**撤回，不再约束 AB-001P2**。

当前正确原则由 `D-017_政治中心先总体容量后单体尺度.md` 接管：

> 小批次限制的是一次施工承担的目标数量与范围扩张，而不是把主要建筑强制缩小。

三席议事大厅最终尺寸必须由政治中心总体容量、功能、历史参考、Minecraft 尺度与实际 Site 共同推导。
