Owner 在 AB-001P1 的 A / B 消歧后明确选择：

> **A**

因此三席议事大厅第一 Pilot 的当前 Site Anchor 固化为：

此前 Owner 使用的“西部平岛的中心岛”是视觉/空间指称。后续正式规划不得再把 A 错写为独立岛或 west land component 1。

这次确认只关闭 Site mapping，不等于 world-write authorization。

## 2. First Pilot Scope

第一 Pilot 的主要目标只有：

> **三席议事大厅（Three-seat Council Hall）**

不得因为 Site 是未来联盟政治中心而在同一施工任务中顺带建设：

- 联盟大广场；
- 三域代表馆；
- 档案馆 / 金库 / 裁判庭；
- 完整码头；
- 跨岛桥；
- 道路网；
- 大规模园林；
- 成片城市街区；
- 其它第二主要建筑。

这些可以作为未来空间关系被预留，但必须拆成独立后续任务。

## 3. Bounded Construction Principle

Owner 明确要求：Codex 施工不要一次承担过多建筑或过大范围。

以后本项目默认：

> **一个 world-write Task = 一个主要建筑 / 一个主要空间目标 + 为其成立所必需的最小接口。**

“最小接口”可以包括有限的：

- 建筑基座；
- 入口前场；
- 几格范围的接路 / 台阶；
- 必需挡土墙；
- 紧邻建筑的地表整理与结构性植被调整。

不得把“周边顺便完善”解释成扩大施工范围。

### Pilot-specific size guard

对三席议事大厅第一版本：

- 主体建筑 footprint **目标 <= 45 × 45 blocks**；
- 若形态确有必要，可允许单一方向适度延长，但超过约 52 blocks 前必须说明设计理由；
- 第一批 world-write 的总 site intervention envelope **目标 <= 64 × 64 blocks**；
- 不得把 AB-001P1 识别出的 79×79 FLAT 诊断区整体视为可施工范围；
- 不得进行整片湾内低地的大尺度推平、填水或重做景观。

数值是 scope guard，不要求建筑必须方形，也不是强制填满上限。

## 4. Delivery Sequence

当前采用：

```text
A Site confirmed
→ bounded Architecture Design
→ Architect / Critic / Revision
→ single-scheme Preview if useful

→ separate explicit bounded world-write Task
→ in-game validation
→ next adjacent target only after acceptance
```

设计阶段仍 `world writes = 0`。
