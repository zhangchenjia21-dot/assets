# D-017｜政治中心先总体容量、后单体尺度

状态：**OWNER CORRECTION / ACTIVE DECISION**

日期：2026-09-10

## 背景

AB-001P1 选定 Candidate A 作为三席议会政治中心的空间锚点后，D-016 曾为防止 Codex 扩大施工范围，给三席议事大厅预设 `<=45×45` 主体 footprint 与 `<=64×64` 第一批 intervention envelope。

Owner 随后指出：施工必须小批次，但**单体建筑尺度不能由“小批次”反推**；在确定大厅大小前，应先考虑：

- A 场地总面积与真实可用地形；
- 未来政治中心可能需要的其它建筑；
- 公共空间、岸线、景观与扩建余量；
- 三席议事大厅自身的制度功能与前现代公共建筑尺度；
- 建筑尺度是否与 CIV-001 的政治地位、技术水平和 Minecraft 可读性相符。

该修正有效。

## 决策

### 1. 小批次 ≠ 小建筑

继续保持：

> **一个 world-write Task = 一个主要建筑 / 一个主要空间目标 + 必需最小接口。**

但不得把这条原则解释为“主要建筑必须很小”。

建筑尺寸必须由：

```text
Site capacity
+ long-term precinct program
+ building function
+ historical / typological references
+ Minecraft scale / readability
+ terrain fit
→ individual building size
```

推导。

### 2. D-016 的固定数值 guard 撤回

D-016 中以下 pilot-specific 数字：

- `<=45×45` footprint；
- 单方向约 `52` 格说明门；
- `<=64×64` intervention envelope；

**不再作为 AB-001P2 的设计约束。**

它们是此前为了防止 scope 膨胀设置的未经完整容量计算的保守数值，现由本决策纠正。

D-016 的 Site A 选择与“小批次施工 / 单目标施工”原则继续有效。

### 3. 先建立政治中心容量规划

在三席议事大厅尺寸冻结前，必须先形成一个轻量的 `Council Centerland Program / Capacity Plan`，至少回答：

- A 场地真实总量级；
- 长期政治中心只应占用 A 的多少比例；
- 哪些未来功能需要独立建筑 / 可合并建筑 / 只需预留；
- 建筑总 footprint、公共开放空间、岸线 / 景观缓冲、扩建余量如何平衡；
- 三席议事大厅应处于什么 footprint / 长宽 / 高度量级；
- 第一 world-write 批次应如何围绕最终大厅方案重新限定，而不是提前套固定方框。

### 4. 总体规划可以大，施工任务仍必须小

允许先对整个政治中心形成**非施工型总体容量与关系规划**，用于避免第一座建筑占错位置或压缩未来空间。

但后续真实施工仍必须拆分：

```text
precinct capacity / reservation plan
→ single building design
→ single building bounded world-write
→ Owner in-game review
→ next building / space
```

总体规划不得自动变成一次性建设授权。

## 当前影响

- Site A 选择：继续有效；
- AB-001 Architecture Grammar：继续有效；
- AB-001P2：在容量规划完成 / 接受前暂停；
- `world writes = 0`；
- 不因本决策自动创建政治中心布局或施工边界。
