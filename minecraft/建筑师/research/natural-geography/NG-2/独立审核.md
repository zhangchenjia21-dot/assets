## 3. 数据与方法审查

### 3.1 不是粗网格插值

实现实际读取 DataVersion 4903 region / chunk / palette 数据。背景采用 8-block actual grid，关键区域按 slope / water transition / target radius 细化到 4 blocks；水拓扑目标使用完整 1-block ROI，山口使用 1-block 核心，并为每个 target 保存四条逐列 profile。

因此本轮属于真实局部再采样，不是把 V1 64-block cell 插值放大。

### 3.2 水体拓扑

水体连通使用真实 block-state 水柱，并要求四邻柱的 `[water_bottom, water_top]` 区间至少共享一个 Y。没有用 river / ocean biome 代替连通性，也没有跨对角或干桥自动连通。

这使 `SITE-003` 的岛屿闭合判断，以及 `SITE-019` 的开放水系重分类，具有足够强的 block-level 证据。

### 3.3 山口语义

`SITE-002` 的 1-block 核心证明 V1 点邻近存在局部浅鞍部：东西向保守步进路径最高 Y=621，且目标南北 64 格显著高于东西 64 格。

但该算法不是完整 Minecraft entity pathfinding，也没有证明整个山脉的战略穿越路线。因此审核接受 `local_rocky_ridge_saddle`，不接受无约束的 “confirmed mountain pass” 扩张解释。

### 3.4 Semantic verdict 与算法分离

最终 verdict 来自明确保存的 interpretation 层，交付整理流程只把解释与 metrics / provenance 绑定并校验字段，没有使用一个“达到阈值即自动 PASS”的 detector 替代语义判断。

两处 RECLASSIFIED 说明本轮没有为了提高 V1 命中率而回避反例。

## 6. Notes / Residuals

### N-01｜Safe visual review 仍缺失

`BLOCKED_BY_SAFE_ENVIRONMENT` 符合 Task Packet 允许条件，不阻塞 NG-2 离线调查验收。

但以后在把某个地点用于重要世界地名、建筑选址或视觉景观设计前，应在存在真正零写入 Observation 路径时补做现场视觉复核。

### N-02｜局部 CONFIRMED 不等于全局 detector 已校准

八点只是一组代表性 calibration evidence。NG-3 不得由“6/8 confirmed”推出 V1 全世界 1,264 GEO / 412 HYD / 1,343 FEAT 都可信。

### N-03｜面积与边界不能过度解读

`SITE-015` plain、`SITE-014` tableland、`SITE-017` mountains 的部分 mask 触及 ROI 边缘。对应面积只能作为已观察区域内的规模下界 / sampled estimate，不是完整自然地理对象面积。

### N-04｜海湾不等于天然港

`SITE-011` 足以支持 multi-opening coastal embayment，但水深、航道、入口法向宽度、潮流等均未验证。后续不得从 `coastal_bay` 自动推导 `natural_harbor`。

### N-05｜人工污染来源仍不确定

八个目标都保留 `anthropogenic_contamination = possible`。Waystone 和部分材料存在，但生成结构 / 玩家改造来源不能完整恢复。后续自然史只能描述当前可观察地表，不得伪装成“玩家进入前原始地貌复原”。

### N-06｜仍不推断流向

NG-2 水体拓扑比 V1 强很多，但依然只是表层连接关系。河流上下游、真实汇流、水源与流域需要独立任务才能建立。
