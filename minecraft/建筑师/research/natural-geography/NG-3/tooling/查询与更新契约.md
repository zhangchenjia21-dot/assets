# 查询、数据与更新契约

## 数据关系

`atlas.sqlite` 为 Proposed Atlas 查询事实源；`atlas/objects.jsonl`、`relations.jsonl` 是导出，`visual/` 是派生阅读视图。解释决定单独保存，数值分段程序没有地貌语义裁定权。

| 表 | 契约 |
|---|---|
| meta | schema、算法、execution base、freshness as-of、覆盖范围与全局警告 |
| atlas_objects | 固定 ID、family/type、PROPOSED、evidence_status、machine_label、geometry_id 与完整 details JSON |
| geometry_runs | 闭区间整数矩形 `(x0,z0,x1,z1)` 的并集；RLE 存实际成员，不是对象 bbox |
| atlas_members | 几何与 64-block cell 相交索引，只供检索/lineage，不表示整格包含 |
| cell_index | V1 cell 的标量事实、历史 GEO ID、未归并陆/水标记 |
| lineage | 每对象的 V1 / NG-2 引用、cell 回溯、算法；引用中的角色区分校准与直接局部支持 |
| relations | source/target/kind/evidence_status/evidence；支持 adjacent_to、contains、part_of、connected_to、associated_with、overlaps |
| uncertainty | boundary/topology/semantic/requires_refinement；与对象 details 一致 |
| calibration | 八个 NG-2 局部校准规则及禁止晋升范围 |
| identity_registry | stable_key、geometry_signature、PROPOSED/RETIRED ledger |

`geometry.bounds` 是包围盒摘要。region runs 是裁剪后的 64 格近似，局部水面/岛屿为 1 格真实 mask，台地为 8 格采样 mask，鞍部/海湾及 NSITE 为单点。1 格水面 mask 只证明 ROI 内已观察到的连续水柱关系。模型没有为点对象补造面状边界。

## 查询行为

- `coordinate`：实际命中成员、附近三个 NGEO、512 格内水体/features、最近 NSITE、cell、证据状态、不确定性与 lineage 摘要。负坐标按 floor 除 64；世界范围外明确 OUTSIDE，最近对象不代表覆盖。
- `object`：完整对象和完整 lineage。
- `neighbors`：所有入/出关系以及对象摘要；应读取关系 kind，不把关联自动视为连接。
- `search`：family/type/evidence-status 精确过滤，AND 组合，无模糊匹配。
- `context`：对成员矩形/点取最小欧氏距离，返回半径内对象及内部关系，附落点上下文、校准和约束；不按 centroid/bbox 选取。没有文明或建筑生成。

所有命令使用只读 SQLite URI，连接在 finally 关闭；对象与键排序固定。坐标/半径为整数，radius 非负。未知 ID、负半径返回 schema JSON error 和退出码 2；argparse 的非法参数保持标准 usage 错误。摘要保留所有非 V1 lineage 与前三个 V1 引用，完整数据通过 `object` 获取。

## 稳定 ID 与更新

本轮算法 `ng3-consolidation/1.0`；ID 从数值候选初次分配后写入 `atlas/id-registry.json`，NG-2 局部对象以来源 SITE 绑定。固定输入重建不得重编号。工具验证 stable_key 与成员几何 SHA256；几何漂移、重复 key 或 RETIRED ID 重用立即拒绝。此保护不是自动解决未来变化的匹配器。

未来更新必须先比较成员重叠与证据 lineage，再由明确语义决定确认是否保持同一自然对象；不得仅按面积/排序/阈值自动认定身份。保留 ID 时提交显式 continuity 决策及新旧几何签名；拆分/合并分配新 ID，记录 predecessor/successor lineage，旧 ID 标 RETIRED 且永不回收。当前工具遇到此类变化会停止，需另行授权实现并审核对应迁移，不能直接删除 ledger 重跑。新 ID 在审核前仍为 PROPOSED。

## 构建复现

验证环境：Python 3.12.14、numpy 2.3.5、Pillow 12.3.0、nbtlib 2.0.4、Windows。查询只依赖标准库（已用 `python -S` 测试）；build/segments/tests 用 numpy，views 用 Pillow；freshness gate 用 nbtlib + Win32 只读句柄。地图字体为 `C:/Windows/Fonts/arial.ttf`。Bootstrap 为原工作区保留 nbtlib vendor 路径；其他机器可正常安装 nbtlib，无需该路径。

已发布快照可直接 query；重建从已冻结数值分段与语义决策开始：

```powershell
python tooling/Bootstrap/图册命令.py prepare
python tooling/Bootstrap/图册命令.py segments
python tooling/Bootstrap/图册命令.py build
python tooling/Bootstrap/图册命令.py views
python tooling/tests/图册验证.py
```

需要 sibling V1 的 `survey/raw/geography.sqlite.gz` 以及 sibling NG-2 的 assessments/NPZ。prepare 解压到本 NG-3 被忽略的 input-cache，保留 SHA256，不修改历史证据。不需要解压或复制 NG-2 大 SQLite。

当前已存在初始 gate，禁止覆盖；其初始/final 命令分别为：

```powershell
python tooling/Bootstrap/图册命令.py gate --world '<建筑师存档绝对路径>'
python tooling/Bootstrap/图册命令.py seal --world '<建筑师存档绝对路径>'
```

两者仅核验，不启动游戏。世界及历史证据现有文件在核验期间持 GENERIC_READ / FILE_SHARE_READ 句柄，并比较完整文件 inventory/hash。新任务需要新的输出快照，不能通过覆盖当前初始 manifest 重置比较基线。freshness 以 Overworld region SHA256 为准；完整世界变化另报，不把玩家/时间变化冒充地形改变。

四层模块仅位于 tooling，依赖向下，Bootstrap/tests/docs 属工程外围；不引用 NG-2 内部模块。所有研究脚本输出只在 NG-3，世界和历史证据均只读。
