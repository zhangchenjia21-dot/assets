## 2. Atlas consolidation 是否真的解决 V1 碎片化

V1 原有 1,264 GEO / 412 HYD / 1,343 FEAT / 20 SITE，明显属于 survey-level 碎片索引。

NG-3 收敛为：

| Family | Count |
|---|---:|
| NGEO | 35 |
| NHYD | 20 |
| NFEAT | 4 |
| NSITE | 8 |

总计 67 个长期 Atlas 对象，数量与粒度已经进入“人类和 Codex 可理解的宏观自然区域 / 水域 / feature / observation site”量级，没有继续把上千 V1 组件照搬成新 ID。

35 个 NGEO 的语义并非由 terrain 字符串自动命名。实现先以 elevation / 320-block neighborhood / relief / water barrier / four-neighbor continuity 生成数值候选，再由显式 `semantic-decisions.json` 结合地图与 NG-2 校准赋予宏观解释。

审核接受这种分层：

`Observed / V1 coarse facts → numerical segmentation → model semantic decision → Atlas object + uncertainty`

但宏观 region boundary 仍主要是 64-block proxy，并受 320-block smoothing 与 small-component merge 影响，因此只适合作为规划索引，而不是精确施工边界。

## 4. NG-2 calibration 是否真正吸收

八条 NG-2 结论已经成为机器可读 calibration rule，而不是被写成“6/8 = 75% detector accuracy”。审核重点核对的边界均保留：

- `SITE-002`：只允许 local saddle，不得提升为 strategic mountain pass / whole-mountain traversability；
- `SITE-005`：保留 mountain-front apron + river lowland 重分类，不建立 broad valley；
- `SITE-015`：平原只作为 low-relief context，不把代表点当完整平原中心；
- `SITE-014`：保留 local bench/tableland，不宣称完整 closed plateau；

- `SITE-011`：只保留 local multi-opening coastal embayment，不产生 natural harbor / unique mouth / navigability。

因此 NG-3 没有静默覆盖 NG-2 的两个反例，也没有把局部 confirmed 结论外推成全球 detector 真值。

## 7. Query layer 审核

`atlas.sqlite` 是主查询事实层；JSONL 是导出，PNG 是派生阅读视图。

提供五个主要查询：

- `coordinate`
- `object`
- `neighbors`
- `search`
- `context`

查询实现使用 `geometry_runs` 的真实 indexed members / rectangles / points 计算命中和距离，不用 bbox 或 centroid 假装 footprint。

`context` 会返回：

- coordinate context；
- radius 内 objects；
- relations；
- uncertainty / calibration / global constraints；
- `world_write_authorized=false`；
- `design_or_canon_generated=false`。

因此它适合作为以后 Codex 的自然地理“上下文入口”，且没有越权进入设计或写世界。

自动验证还覆盖 stdlib-only CLI、确定性 JSON、错误路径、150 个固定种子随机坐标、负坐标、边缘坐标、NG-2 actual masks 和非矩形 gap。

## 10. Review Notes / Residual Limits

### N-01｜宏观边界仍是尺度化代理

除 NG-2 actual-mask 局部对象外，多数 NGEO / coarse NHYD 仍主要来自 64-block grid + 320-block smoothing。Atlas 可以回答“宏观上这里是什么环境”，不能直接回答“城墙边界应精确落在哪一格”。

### N-02｜全球真实水系仍未建立

河流流向、流域、汇流、水源、全球真实连通均保持 unknown。进入 Human Geography 后，可以用水域作为交通/资源 hypothesis，但不能未经局部验证就冻结港口或航道 Canon。

### N-03｜65 / 67 对象仍需要 refinement

这不是 NG-3 失败，而是说明本 Atlas 的目标是“稳定索引 + uncertainty”，不是把每个自然对象都做成 survey-grade exact boundary。

### N-04｜0 targeted refinement 是合法但有代价的选择

本轮没有为了填补未知额外扫描世界。审核接受，因为现有证据已足以建立宏观 skeleton，且未把未知水体/山口强行 promotion；代价是许多 local/topological questions 仍必须在未来按需 refinement。

### N-05｜无安全游戏内视觉复核

仍为 `BLOCKED_BY_SAFE_ENVIRONMENT`。这不阻塞 Natural Atlas 的离线规划用途，但任何重要 site promotion / Canon build 前仍应执行 local terrain verification，并在安全 Observation 能力可用时补玩家视角观察。

### N-06｜Artifact 内部 `PROPOSED` 与外部 promotion 语义

为保留 rebuild/hash 证据，本次不修改交付快照内部状态。以后 Codex 必须读取 `current/项目状态.md` / architecture contract，理解：

- `57d392d...` 整体快照已被独立接受为 Current Natural Atlas planning baseline；
- artifact 内 `status=PROPOSED` 是生成时的历史状态；
- `evidence_status=SUPPORTED/PROVISIONAL` 与 uncertainty 仍持续有效；
- 这项 acceptance 不等于 World Canon acceptance。
