# 拓展包创作模板

配套规范：`DSH-native_创作总规范_v0.1.md`。拓展包为游戏增加一个**可玩机制域**——不是重建一套 Runtime，也不是把机制写成纯设定。

## 一、文件与命名

- 通用机制：`拓展包/通用拓展包/名称_Expansion_Pack_vX.Y.Z.md`
- 世界专用：`拓展包/作品名/作品名_名称_Expansion_Pack_vX.Y.Z.md`
- Core-first：多个世界共享的机制先做通用核心，再做世界专用下游（总规范 7.3）。
- 范例：`../拓展包/通用拓展包/战斗核心_Expansion_Pack_v0.1.md`

## 三、章节骨架

### 开篇双 callout（必备）

```markdown
> [!abstract] 这份拓展包是什么
> 两句话：它为游戏增加什么体验、它的边界是什么。

> [!important] 启用方式
> 本包是可选内容，经玩家明确选择后启用；未启用时 GM 按世界常识自然裁定，不假装机制存在。
```

### 正文章节（按需取舍，标 ★ 为必备）

| 节 | 内容要点 |
|---|---|
| ★ 这个包为游戏增加什么 | 体验价值先行：玩家会感觉到什么不同 |
| ★ 机制何时成立 | 进入 / 退出本机制域的条件；防止把一切行动都纳入结算 |
| 核心概念 | 领域术语定义，用"X 不是 Y"划界句（总规范 5.4） |
| ★ 机制本体 | 语义阶梯（代码块）、状态区分、对抗结构——保留真实可玩区分 |
| ★ 裁定方式 | GM 思考顺序箭头链（总规范 5.2）；声明不锁死公式 |
| ★ 何时值得正式裁定 | 真实不确定 / 成败有意义 / 合理可尝试 / 有对抗风险 |
| 失败与代价 | 失败、成功、僵持、恶化分别在游玩中是什么感觉 |
| ★ 长期状态清单 | 哪些事实值得长期记住（只列事实，不写存储——总规范 5.5） |
| ★ 这个包不拥有什么 | 逐条划界并指明归属方 |
| 常见误区 | 预期 GM 会犯的错，先堵 |
| ★ 与其他资产的关系 | 逐条协同 / 降级双写（总规范 4.2） |

### 收尾（必备）

- **相关资产**：相对路径链接清单；
- **Revision Notes**。

## 四、写作要点

1. **机制不拍平**：层级、裁定流程、对抗窗口等改善游玩的区分必须保留；删掉的是运行时管路，不是机制深度。
2. **语义阶梯优先于数值**：`轻微 → 明显 → 沉重 → 极端` 优于伤害公式；数值只在真正改善游玩时保留。
3. **目录不是白名单**：法术目录、技能清单、动作类型都是示例与参考，不删除玩家的合理 Attempt（总规范 1.4）。
4. **移交而非吞并**：本机制产生的后果属于其它领域时（伤势→身体状态、名望→社会评价），写"移交 X 领域裁定"，并写清对方未启用时怎么办。
5. **因果而不是仪式**：机制存在是为了让世界因果更可信，不是为了每回合走流程；琐碎行动直接叙述带过。

## 五、检查表

- [ ] 开篇双 callout 在；启用方式为显式玩家选择
- [ ] 机制成立 / 不成立的条件清晰
- [ ] 核心概念有划界句
- [ ] 裁定是思考顺序，无锁死公式；语义阶梯代替数值
- [ ] "何时值得正式裁定"节在
- [ ] 长期状态清单只有"记什么"，无"存哪 / 怎么存 / 何时更新"指令
- [ ] 不拥有清单逐条有归属方
- [ ] 每条协同关系都有降级写法；本包独立完整可用
- [ ] 无机器依赖字段、无运行时概念残留
- [ ] 相对路径链接有效；Revision Notes 已更新
