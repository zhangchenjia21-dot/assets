# 乱世三国｜区域地图制图规范

## 0. 定位

本文件是 Level 2 区域地图 Rule Owner。

区域图不是把天下图机械放大，而是帮助玩家理解一个地区如何生活、旅行、通行、阻隔并发生故事。

原则：

> **继承 Level 1 已冻结的事实与视觉成本，只补区域级信息。**

生产协作、Gate 哲学和已验证的 AI 制图经验另见：

> `00_当前规范/制图生产经验与AI协作规范.md`

## 1. 继承链

```text
Level 1 历史 / 地理事实
→ Level 1 已确认的相对空间关系
→ 本区域新增考据
→ Regional Artwork Space
→ 区域美术与文字
```

不得重新决定已锁核心城市、一级山河和关键邻接关系。只有发现明确新证据时才回到对应 Data Owner 修正。

## 2. Fact Space / Regional Artwork Space

Fact Space 负责历史点位、山河拓扑、交通事实、行政与时代信息。

Regional Artwork Space 负责最终画布、视觉面积、道路可读宽度、标签安全区和环境叙事强化。

区域图允许比天下图更强的局部游戏化形变，但必须保持：

- 山河两侧关系；
- 城市和道路拓扑；
- 关键门户；
- 区域出入口；
- 相邻地点顺序。

审核以“拓扑 / 叙事关系是否成立”为核心，不要求所有对象逐像素复刻现代 GIS 或参考图。

## 3. 视觉 DNA

必须继承 Level 1：

- 温润米黄 / 淡绢色底；
- 墨青、灰绿、赭石山体；
- 石青 / 灰蓝水系；
- 低至中饱和；
- 古意而不做旧；
- 真实简体中文；
- 同源城市、聚落、关隘、道路、渡口与地标符号语言。

区域图允许增加山水绘卷感、林地、湿地、农田、水乡、城郭和聚落，但不能变成卫星图、现代 GIS、SLG 彩色行政沙盘或泛奇幻 RPG 地图。

## 4. 区域差异

地方性格来自真实地理与生活方式，不来自装饰：

- 关中：渭水、平原、秦岭北麓、驿道、关口；
- 荆襄：汉水、江汉湿地、渡口、湖沼；
- 巴蜀：盆地、山道、剑阁 / 三峡门户；
- 江东：江河湖网、水乡、丘陵、港口；
- 河北：大平原、太行东麓、北方交通轴；
- 凉州：走廊、戈壁、绿洲、山前通道；
- 兖豫青徐核心区：黄河 / 淮水与平原交通、高密城邑、山东丘陵—平原—海岸过渡、多州 Narrative 交汇。

## 5. Density Profile

区域图不使用唯一固定信息预算。开图前先选择密度类型：

### 5.1 standard-region

一般区域。保持较强留白，优先表达少量关键城市、主交通与地方地理。

### 5.2 corridor-region

走廊型区域。适合关中—弘农—雒阳等“平原—门户—狭道—平原”结构，主轴和道路优先。

### 5.3 high-density-important-region

适合荆襄、中原核心、江东核心、巴蜀核心等高频叙事区。

2K 全屏下允许：

- 约 `18–24` 个城邑 / 地点；
- 约 `8–14` 个 Narrative / 关隘 / 渡口 / 港口节点；
- 约 `7–10` 条主次交通骨架；
- 约 `12–18` 个自然地理标签；
- 少量低对比行政背景。

数字只是预算，不是凑数要求。

原则：

> **提高有叙事和交通价值的信息密度，不提高行政百科密度。**

## 6. 信息优先级

```text
核心城市 / 高价值地点
> 关隘 / 渡口 / 交通节点
> 主道路与河流
> 次级城市 / 聚落
> 山岭 / 湖泽 / 地标
> 必要行政标签
> 装饰
```

区域图不做行政百科，不要求显示所有郡县。

发生碰撞时，不应第一反应整体缩小文字；先移动标签、删除最低价值对象、调整背景行政信息。

## 7. 城市与新增地点

Level 1 已有城市继承 identity 与大尺度关系，只映射到新的 Regional Artwork Space。

新增县邑 / 聚落至少满足一项：Narrative 高频、政治经济价值、交通转折、历史事件、渡口港口山谷入口或玩家空间认知不可替代。

不要为了填空机械增加县邑。

### 7.1 Historical Identity / Display Object

玩家显示名可以服务现代玩家认知，但不得改写历史事实。

数据建议区分：

- `historical_identity`；
- `display_name`；
- `display_role`；
- `historical_parent`；
- `display_region / display_macro_state`。

例如历史城邑与玩家熟悉的现代区域称呼可以同时存在，但必须明确各自职责，不自动当成两座同级历史城市。

## 8. 道路、水路与交通

Level 2 正式承担交通表达。

道路用于说明城市如何连通、哪些路穿山、哪些路线沿河、哪些关口控制交通。

建议分为：一级主干、二级道路、少量高价值山道 / 栈道。

禁止现代公路线型、直线穿山、无渡口语义跨越大河、把所有可能道路全部画出。

水路地区应同时表现高价值渡口 / 港口，但不使用现代航线 UI。

### 8.1 水路审核原则

“水路枢纽”不要求城市 Anchor 必须逐像素压在现代意义的精确汇流点。

只要满足：

- 河网拓扑和方向成立；
- 城市通过合理水路可达；
- 主河 / 次河层级清楚；
- 港口 / 渡口承担正确 Narrative；

即可接受 Artwork Space 的适度舒展。

## 9. R4 无字区域底图

R4 的职责不是单纯“画得好看”，而是为正式 Overlay 提供可用空间。

至少检查：

- 核心城市有稳定落位区；
- 主道路有可通行地形；
- 河流主次清楚；
- Narrative 主轴在无字状态可读；
- 未来标签有足够安全区；
- 高密版区域仍有连续陆地或可居住空间。

### 9.1 湿地 / 水乡硬规则

AI 容易把“湿地丰富”放大成大面积永久水面。

因此以后涉及云梦、江东水乡、湖网地区时必须明确：

> **水网丰富 ≠ 水面占多数。**
>
> **湿地平原 ≠ 群岛。**

应明确连续陆地、湖沼面积、主河等级、城市预留区和湿地集中区。

类似地：

> **山地重要 ≠ 满屏碎山。**

## 10. R5 描点、符号与文字

### 10.1 R5-A / R5-B 可合并执行

对象量可控时，外部图像执行 AI 可以一次完成：

- Regional Anchor Calibration；
- Anchor Review；
- 正式 Overlay。

但必须保留 Anchor Review 供技术审核检查拓扑。

### 10.2 文字

- 正式文字使用真实简体中文字体；
- 城市、聚落、关隘、渡口、山河有不同层级；
- 标签可偏移，不移动事实节点；
- 必要时使用短、克制 leader line；
- 默认 16:9，Pilot 审阅 `2560×1440`；
- 保留无字底图、标准标注版与可编辑 Overlay。

## 11. 生产与审核角色分离

区域图设计 / 审核与图像生成可以由不同 AI 承担。

技术设计 / 审核 AI 负责：

- Authority 与 freshness；
- R0–R3；
- 对象与数据架构；
- Prompt；
- 拓扑 / 历史 / 信息密度审核；
- Gate 与仓库写回。

图像执行 AI 负责：

- R4 生图 / 修图；
- R5 Anchor Review；
- 正式 Overlay / 导出。

技术设计 / 审核 AI 不需要、也不应同时承担项目生图角色。详见 `制图生产经验与AI协作规范.md`。

## 12. 简化流程

Level 2 不重复天下图完整 Gate 链。

```text
R0 范围与 Narrative 目标
→ R1 继承 Level 1 事实骨架
→ R2 补区域点位 / 道路 / 渡口
→ R3 游戏化构图
→ R4 无字区域底图
→ R5-A Regional Anchor Review
→ R5-B 确定性符号与文字
→ R6 QA / Owner Review
```

只有新的高风险事实争议才插入专项考据。

## 13. 返工判定

### 13.1 需要重新生成 R4

- 大尺度地理拓扑错误；
- 水陆比例严重错误；
- 主要城市没有稳定落位空间；
- 主 Narrative 轴无法成立；
- 区域视觉类型根本不匹配。

### 13.2 只做 Overlay 局部修订

- 标签偏移；
- 次级 Anchor 微调；
- 道路线宽 / 对比度；
- 城市 / Narrative 标签碰撞；
- Display Name 调整。

不要为了修一个标签重新生成整张底图。

## 14. QA / Gate 哲学

通过前至少确认：

- 核心城市与 Level 1 关系一致；
- 山河方向可信；
- 道路不穿越不可能地形；
- 关隘 / 渡口控制真实通道；
- 玩家能看懂主要旅行轴；
- 高频地点优先，低价值行政信息没有挤占空间；
- 与 Level 1 属于同一视觉世界；
- 地区性格明确；
- 文字真实可读；
- 第一眼能分辨城市、道路、山河和门户。

Hard blocker 与 soft issue 分开。

只要：

> **游戏逻辑能讲通、主要地理大致正确、2K 可读、没有误导性硬错误，区域图即可通过。**

不追求“百分比完美”。

## 15. 已验证 Pilot

### L2-01｜关中—弘农—雒阳

验证：

- `corridor-region`；
- 陆路、关隘、山河控制；
- R5-A + R5-B 合并执行可行。

### L2-02｜荆襄—江汉

验证：

- `high-density-important-region`；
- 高密城市 / Narrative / 行政背景在 2K 可同时成立；
- 水陆复合交通；
- 湿地必须防止“群岛化”；
- 玩家 Display Name 与历史 identity 应解耦。

后续区域不再以“再次验证模板”为主要目标，直接进入内容生产。
