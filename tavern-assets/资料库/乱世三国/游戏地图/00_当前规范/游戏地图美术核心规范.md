# 乱世三国｜游戏地图美术核心规范 CURRENT

## 0. 文档职责

本文件是《乱世三国》游戏地图美术资源的当前核心规范，记录正式地图生产已经冻结的产品定位、层级、视觉语言、文字规则、历史真实性边界、基础地图美术职责与源资产生产原则。

本文件服务于 `my world` 的地图美术创作，但**不定义游戏本体 Runtime / UI / World Pack 的机器 Schema、Asset Contract、动态势力数据或交互实现**。尚未由游戏本体证明和授权的技术协议，不在本文件中提前冻结。

当前地图工作遵循：

> **先冻结难以低成本修改的美术方向，再以中立地理总图开始真实生产。**

同一文档族 active 目录只保留一个 current；后续修订优先更新本固定路径，历史由 Git history / archive 承担。

# MAP-DEC-01｜产品定位：叙事世界地图优先

《乱世三国》的地图首先是一套服务于长期 AI RPG 的**叙事型世界地图**。

核心目标是帮助玩家理解：

- 地点在哪里；
- 区域之间是什么关系；
- 山河与交通如何塑造旅行与故事；
- Narrative 中提到的人物、事件与地点处于怎样的空间语境；
- 玩家正在进入、生活和行动于怎样的三国世界。

地图不以传统 SLG 战略沙盘、角色自由移动地图、GIS / 测绘地图或学术行政复原图为主要定位。

战略、势力与战争信息未来可以成为额外视图或信息层，但**不主导基础地理地图的视觉语言，也不属于当前地图美术开工范围**。

一句话原则：

> **首先让玩家觉得“这是一个我可以生活、旅行、探索和经历故事的三国世界”，其次才是战争发生的棋盘。**

# MAP-DEC-02｜地图层级：三级能力，两级默认生产

《乱世三国》采用三级地图能力体系。

## Level 1｜天下地图

负责整个世界的宏观空间认知，重点包括：

- 天下整体轮廓；
- 主要山河与自然地理骨架；
- 州；
- 经过游戏价值筛选的重点郡国；
- 高价值城市、地点、关隘；
- 长距离空间关系。

## Level 2｜区域地图

负责具体区域内更丰富的叙事与旅行空间认知，可进一步表现：

- 城市与聚落；
- 道路；
- 水系；
- 山岭；
- 关隘；
- 渡口；
- 地标；
- 区域生活与环境特征。

区域划分优先依据**地理与叙事可理解性**，不要求机械地一一等同历史行政州界。

## Level 3｜专题 / 局部地图

第三级不规定单一形态，根据真实内容与叙事需要制作，可以包括但不限于：

- 城市 / 聚落地图；
- 建筑群或特殊地点地图；
- 山谷、关隘、岛屿等局部地理地图；
- 战役 / 战场地图；
- 行军路线图；
- 探索区域图；
- 特殊剧情或事件地图。

正式生产原则：

> **三级是能力体系，不是三级都必须全面铺开。**

默认生产范围为 **Level 1 天下地图 + Level 2 区域地图**。Level 3 仅在地图能够显著增强空间理解、叙事、探索或玩法时制作，不建立“每个城市 / 地点都必须有地图”的资产负担。

# MAP-DEC-03｜视觉风格基线

## 3.1 历史基础 + 适度传奇化表达

地图以汉末三国真实历史地理与文化视觉为基础，允许在不破坏基本地理逻辑与时代可信度的前提下，对山川、关隘、城池和关键地标进行叙事性强化。

传奇感主要来自构图、尺度、氛围、视觉权重与地貌的叙事强化，不通过仙侠化地貌、超自然奇观、泛中国奇幻建筑或与汉末三国时代不相符的幻想视觉制造。

核心原则：

> **可信的三国地理，传奇化的叙事表达。**

天下地图最克制，区域与专题地图可随叙事需要逐步增强戏剧性。

## 3.2 尺度驱动的制图—绘画比例

不同地图层级不要求采用相同的写实 / 绘画比例。

### 天下地图

以**地理可信、信息清晰、制图秩序**为优先，整体更偏写实制图。天下图信息量最大，应控制绘画性，避免山水表现挤占州、郡、城市、关隘与山河标注空间。

### 区域地图

在保持空间关系清晰的基础上，允许明显增加中国山水绘卷式表现，包括山体体积与笔触、林地、湿地、农田、水乡、城墙与聚落及地方性地貌特征。

区域图不只是天下图机械放大，而应让玩家感受到不同地区真正具有不同地方气质。

### 第三级专题 / 局部地图

根据专题目的自由决定写实与绘画比例。战役、城市、险关、探索区域等可采用更强的绘卷感或戏剧表现，但仍须服务具体空间理解。

统一约束：

> **表现密度可以变化，艺术语言不能断裂。**

所有层级共享同一套视觉 DNA，包括基础色盘、山体 / 地貌语言、水体语言、城池与聚落符号体系、道路线型、文字体系、边框 / 题签、图标语言、阴影与高程表达逻辑。

## 3.3 古意而不做旧

借鉴古代舆图、纸绢、中国画线条、传统山形、题签与印章等视觉语言，但保持现代游戏美术的清晰、精细与高分辨率品质。

原则：

> **古意，而不做旧。**

避免依赖重度泛黄、破损、污渍、夸张折痕与过度古董滤镜。地图是游戏对世界的视觉表达，不默认假设玩家正在观看一件出土古物。

## 3.4 色彩方向

以低至中饱和的中国传统自然色为主体，例如温润纸 / 绢底色、墨青、石青、石绿、赭石、灰蓝及少量朱红等强调色。

“乱世”不通过把整个世界永久染成灰黑或血色表达。世界应保留自然生命力；战争、灾荒与特殊局势的强烈色彩留给后续专题表现或游戏本体信息层。

## 3.5 地貌：空间关系可信，叙事价值决定视觉权重

无需追求卫星地形或 GIS 式尺度精确。允许大河适度加宽、山脉体量强化、重要关隘更加醒目、城池图标明显大于真实地理比例，但不能因为构图或装饰而破坏重要空间事实。

原则：

> **空间关系可信 + 叙事意义决定视觉权重。**

## 3.6 整体气质

核心关键词：

> **苍茫 / 厚重 / 自然 / 古朴 / 辽阔 / 有生活痕迹**

地图不能只有山、城、边界与战争信息，还应在适合的尺度表现村镇、田野、道路、渡口、港口、水乡等人类活动痕迹，使世界具有可生活感和旅程感。

# MAP-DEC-04｜地名与文字规则

## 4.1 默认文字

正式游戏地图默认采用：

> **现代简体中文文字 + 汉末三国历史语境专名**

古意主要由字体、版式与美术语言产生，不通过全面使用繁体 / 古字增加普通玩家阅读成本。

现代地名主要用于开发、考据与内部映射，不默认替代历史时期名称进入正式地图。

## 4.2 天下地图正式信息范围与密度原则

Level 1 天下地图的主要实际使用目标是**2K（2560×1440）级 16:9 全屏 GUI**。因此天下图可以比普通侧栏或卡片地图承载更多信息，但仍不追求完整行政复原。

天下地图应包含：

- **全部州级空间标签**；
- **经过知名度、历史价值、政治军事价值、交通价值、叙事价值与游戏使用可能性筛选的重点郡国**；
- **知名度高或价值高的城市 / 地点**；
- **高价值关隘与特殊地理节点**；
- **主要山脉、河流、湖泊与关键自然地理名称**。

不默认全面显示县级行政单位，也**不要求把东汉全部郡国塞入天下图**。行政完整性不得压过游戏可读性；允许省略低价值郡国，或在天下尺度对相邻低价值行政空间做视觉合并表达，但不创造历史上不存在的伪行政实体。

当前 2K 全屏总图的候选池目标量级为：

- 州级标签：全部；
- 重点郡国候选：约 `45–55`；
- 高价值城市 / 地点候选：约 `35–45`；
- 高价值关隘 / 战略节点候选：约 `10–15`；
- 主要山河湖泊等自然地理标签：约 `20–30`。

以上是**候选池预算，不是最终必须显示数量**。最终显示量由 16:9 实际排版、标签碰撞、视觉层级与信息价值决定；允许在排版阶段继续删减。

重点郡国的筛选依据包括：三国历史知名度、政治 / 军事价值、高频 Narrative 使用可能、区域空间认知价值、重要交通 / 边疆价值，以及是否能表达仅靠城市标签无法表达的区域概念。

高价值城市 / 地点 / 关隘的入图标准至少满足一项：历史知名度高、三国重要事件发生地、政治中心、军事重镇、重要交通节点、重要经济 / 文化中心、高频 Narrative 潜在地点、对区域空间认知具有显著帮助。

排版冲突时遵循：

> **高价值具体地点 > 低价值行政完整性。**

例如一个低价值郡名与高价值城市、关隘或叙事地点发生不可解决的空间竞争时，应优先保证具体高价值地点的可读性，而不是为了行政完整把重要地点挤掉。

州、郡、城池、地点、关隘、山脉、河流必须具有不同的视觉层级与标注语言。具体字体、字号、装饰方式在视觉原型阶段冻结，不在本核心文档中提前写死。

## 4.3 区域与第三级地图

区域地图在天下图基础上增加次级城市、道路、水系、山岭、渡口及本区域真正有价值的地点信息。

第三级专题 / 局部地图根据其用途自行确定信息粒度，不要求复制天下图或区域图的完整行政信息。

## 4.4 底图与文字分离

地图视觉底图与文字标注必须分离，长期保留无字资产。

正式生产至少支持：

- 无文字版；
- 标准标注版。

天下地图通常还应保留高信息标注版本，以适应全屏 / 高分辨率查看。

## 4.5 历史异名与争议

对于存在历史异名、不同时期名称变化、现代对应名称、位置 / 隶属争议的地点，应在制作资料中保留 canonical display name、alias、现代对应与必要的来源 / 置信度记录。

**当前天下地图开工不以“先冻结单一历史基准时点”为前置条件。** 第一阶段先建立中立、稳定、可长期复用的天下地理母版；州郡与历史专名在进入正式标注前按具体资料逐项核实。历史基准问题仅在某项标注确实因时代差异无法可靠确定时再局部处理，不阻塞总图地理结构、美术风格与无字底图生产。

# MAP-DEC-05｜历史真实性与游戏化抽象

地图追求：

> **历史与地理关系可信，而非测绘级精确。**

## 5.1 高真实性约束

应尽量依据可靠资料保持可信的内容包括：

- 主要河流流向与汇流关系；
- 主要山脉、盆地、平原、湖泊等自然地理关系；
- 州、郡的大致空间关系；
- 重要城市、关隘、渡口、战略地点的相对位置；
- 决定重大历史事件和交通关系的地理结构；
- 重要自然屏障与交通方向。

地图不仅要让“位置大致正确”，还应使玩家能够理解某些地点**为什么重要**。

## 5.2 允许的制图抽象

在不造成玩家实质性空间误解的前提下，可以为了可读性与叙事表现调整城池 / 地点的视觉尺寸、河流视觉宽度、山脉视觉体量、道路表现、标签位置、局部排布与高价值地点的视觉权重。

正式优先级：

> **关键历史 / 地理关系 > 玩家空间理解 > 信息可读性 > 艺术构图 > 装饰细节**

## 5.3 历史与文学 / 大众记忆

地图的基础空间事实以历史地理为依据，不以《三国演义》或大众文化印象修改基本地理关系。

但文学、历史事件和大众知名度可以提高某地点在地图上的视觉与标注权重。

原则：

> **历史决定它在哪里；叙事价值决定它有多醒目。**

## 5.4 史料不确定

允许史料存在不确定性。有争议的地点优先使用主流或当前最有依据的判断；如不存在明确共识，为当前地图选择 canonical 表达，并在制作记录中保存依据、争议与置信度，不把美术表现误当成未经说明的绝对历史事实。

## 5.5 稳定地理与游戏状态分离

山河、主要地理位置等稳定事实适合进入基础地图。

势力归属、战争状态、角色位置等会随游戏进程变化的内容不永久烘焙进通用基础地图。

## 5.6 未来需求记录｜Level 1 天下势力视图

长期产品曾明确希望 Level 1 天下地图未来可提供与天下地理图切换的**天下势力图**：在相同天下空间基准上简化地理信息，把视觉重点让给势力范围。

该条**仅作为未来需求记录**：

- 当前地图美术生产不制作势力范围图；
- 当前地图美术不研究势力配色、控制区算法、动态更新或视图切换；
- Level 2 区域图与 Level 3 专题 / 局部地图不规划独立势力范围视图；
- 势力状态、动态更新、控制权语义、Runtime 数据绑定与渲染逻辑全部属于 `my world` 游戏本体职责。

当前地图资产生产以**中立地理信息**为准。

# MAP-DEC-06｜基础地图美术职责与可扩展性

## 6.1 可以进入基础地图的内容

基础地图美术负责相对稳定的世界空间事实和环境表达，包括：

- 海岸与水域；
- 地貌；
- 山脉；
- 河流 / 湖泊；
- 州郡 / 区域空间；
- 城市 / 聚落；
- 关隘；
- 稳定地标；
- 必要道路；
- 地名标注。

## 6.2 不永久烘焙的动态游戏状态

以下内容默认不画死在基础地图中：

- 势力控制色；
- 玩家当前位置；
- NPC 当前所在地；
- 军队位置；
- 当前战线；
- 任务目标；
- 临时事件；
- 行军箭头；
- 当前危险区域；
- 当前外交状态。

原则：

> **世界长什么样，可以进入地图；这一局现在发生什么，不永久画死在地图里。**

## 6.3 为未来信息显示留视觉空间

即使当前聊天不负责 Runtime Overlay，实现前的基础地图仍应避免视觉过载：不把所有平原铺满复杂纹理、不在关键城池周围堆满装饰、不让所有区域都使用强烈底色、关键地名与节点之间保留足够间隔、重要区域保持清楚、底图色彩与对比度不天然压过未来可能的游戏信息标记。

## 6.4 保留可编辑结构

地图母版应尽可能使主要内容可独立修改，包括基础地貌、山地、水系、道路、行政 / 区域边界、城市 / 地点符号、文字与装饰。

当前不提前批量制作缺少真实 UI 需求支撑的任务图标、军队旗帜、玩家箭头等动态地图组件。

# MAP-DEC-07｜源资产与输出规格

## 7.1 生产原则

采用：

> **高质量可编辑母版 → 多用途导出资产**

当前源美术不提前承担未来 World Pack 的正式机器 Contract，但 Level 1 天下地图已经有明确的产品展示目标，因此其**构图与可读性应以 16:9 全屏地图体验为主基线**。

## 7.2 推荐母版尺寸基线

以下为美术生产基线，不是 Runtime 强制规格。

### Level 1 天下地图

- **16:9 横向构图优先**；
- 主要玩家审阅 / 使用目标为 **2K 2560×1440 全屏 GUI**；
- 可编辑母版建议采用 `7680 × 4320`（8K UHD）量级，或同等 / 更高质量的 16:9 高分辨率源；
- 若制作方法能够保持高质量矢量 / 可缩放结构，可以采用更灵活的源尺寸；
- 总图构图应在 2560×1440 等比缩放后仍保持州、重点郡国、城市、关隘和主要山河的分级可读性。

### Level 2 区域地图

- 默认以横向为主；
- 长边通常建议 `4096–6144 px`；
- 具体比例允许随区域自然形态调整。

### Level 3 专题 / 局部地图

- 不统一锁死比例；
- 根据战役、城市、地点和探索区域实际形态决定；
- 通常保持至少 `3K–4K` 级源质量。

## 7.3 可编辑母版

不得采用“最终只留下扁平 PNG、删除原始工程”的生产方式。

母版可以使用 `.kra`、`.psd`、`.svg` 或后续选定的其他合适格式，但应保留主要可编辑层。

尤其要求：

> **文字不得与唯一底图永久焊死。**

## 7.4 通用导出格式

屏幕使用的通用高质量输出优先采用：

> **sRGB PNG**

当前不提前决定游戏最终是否进一步使用 WebP / JPG / Engine import compression；这些属于游戏本体集成阶段的技术选择。

普通完整地图通常不需要透明背景；独立城池、关隘、地图装饰或符号组件如单独导出，则使用透明 PNG。

## 7.5 正式输出版本

所有正式地图至少保留：

1. **无文字版**；
2. **标准标注版**。

天下地图通常额外保留：

3. **高信息标注版**。

条件允许时进一步区分：

```text
纯地理底图
+
地图符号层
+
文字层
```

“无文字版”不等于必须删除所有地图符号；城池、道路、关隘等稳定符号可以保留，重点是文字层可以独立修改。

## 7.6 安全区域与实际审阅

重要城市、标题、核心文字和关键图形不依赖画布最边缘才能成立。母版应保留合理边缘安全区域，以适应未来全屏、裁切预览和不同容器比例。

Level 1 天下地图每次进入正式标注 / 排版审核时，必须至少检查一次 **2560×1440 等比全屏预览**；不能只在 8K 母版 100% 放大状态下判断“看得清”。

当前美术只据此确定画幅和信息密度，不负责设计游戏本体 GUI 控件、交互、缩放或地图打开方式。

## 7.7 版本命名

采用明确的递增版本管理，例如：

```text
L1_天下_地理_母版_v001
L1_天下_地理_无字_v001.png
L1_天下_地理_标准标注_v001.png
```

禁止使用“最终.png / 最终2.png / 真的最终.png / 最新修改版.png”一类无法治理的命名。

命名至少应能识别：

> **Level + 地图对象 + 输出用途 + 版本**

未来如果游戏本体建立正式 machine-readable asset ID，再根据真实 Contract 做映射，不在当前美术阶段提前设计。

## 7.8 参考 / Source / Export 分离

单张正式地图的工作空间建议逻辑上区分：

```text
reference/   # 历史地图、地理资料、视觉参考
source/      # 可编辑母版
export/      # 正式导出成品
```

不要求当前立刻创建所有子目录，但正式生产时应避免把外部参考图与自制成品混放到无法辨认来源。

## 7.9 最小制作记录

每张正式地图应保留最小可追溯信息：

- 地图名称；
- Level / 类型；
- 表达范围；
- 主要参考资料；
- 主动制图抽象；
- 争议 / 低置信内容；
- 当前版本。

如某张地图或某组标注确实依赖特定历史阶段，再补充记录对应历史参考范围；**当前天下地理总图不以预先冻结单一历史基准时点为生产前置条件。**

目标是使后续能够区分：

> **历史事实 / 当前研究判断 / 美术排版调整。**
