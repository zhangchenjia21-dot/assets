# AGENTS.md｜乱世三国游戏地图 AI 读写协议

本文件适用于 `资料库/乱世三国/游戏地图/`，并继承仓库根 `AGENTS.md`。若本文件与根规则冲突，以更严格者为准。

目标：让 AI 用最小上下文完成**地图语义恢复、Owner 定位、正确写回与 Gate 证据管理**。

## 1. 最小读取顺序

### 理解 / 回答

```text
README.md
→ 00_当前规范/游戏地图美术核心规范.md
→ 若涉及天下总图：00_当前规范/天下地理总图制图规范.md
→ 若涉及 Level 2 区域图：00_当前规范/区域地图制图规范.md
→ 若涉及生产工作流 / AI 分工 / Gate 哲学：00_当前规范/制图生产经验与AI协作规范.md
→ 进入唯一相关的数据 Owner
→ 只有追溯依据时读取 02_考据与审核/
→ 默认不读取 99_归档/
```

不要把“读取整个游戏地图目录”当作可靠性策略。

### 正式写回

```text
确认 main freshness
→ 判断信息属于 rule / data / evidence / output / archive
→ 读取唯一 Owner + 必要证据
→ 更新 Owner
→ 检查依赖传播
→ 如形成 Gate 证据，写入 02_考据与审核/
→ 如形成图片，写入 03_产出/
→ 集中汇报
```

## 3. Owner-first 写入

同一事实只能有一个 Owner。

示例：

```text
发现某城市历史点位需要修正
→ 更新 核心点位坐标表
→ 如改变已有历史结论，补充 历史地理核验记录
→ 如影响 Gate 结论，再新增/更新对应 Gate evidence
→ 不在制图规范里复制完整坐标表
```

```text
标准版删掉一个低价值郡国
→ 更新 标准版信息对象表
→ 如高信息版仍保留，再检查变体对象清单
→ 不回头修改已归档的完整候选池
```

```text
新增长期美术原则
→ 更新 游戏地图美术核心规范
→ 若只适用于 Level 1，则更新 天下地理总图制图规范
→ 若只适用于 Level 2，则更新 区域地图制图规范
→ 若是跨地图生产 / AI 分工经验，则更新 制图生产经验与AI协作规范
→ 不创建“补充规范2/最新版”
```

## 4. Rule / Data / Evidence / Output 分离

### Rule
长期有效、指导未来生产的规则，进入 `00_当前规范/`。规则 Owner 原位更新。

### Data
真实坐标、自然地理控制、对象清单等可持续维护的数据，进入 `01_制图数据/`。数据 Owner 原位更新。

### Evidence
历史核验、Gate、Review、审核记录进入 `02_考据与审核/`。Evidence 用于回答“为什么”和“是否通过”，不自动成为 current 规则。

### Output
PNG、母版、结构图、正式导出等进入 `03_产出/`。视觉产物可以有版本号，因为版本本身代表真实产出，不等同文档 current 版本管理。

### Archive
已经被后续正式 Owner 收敛、只需追溯的规划与候选材料进入 `99_归档/`。Archive 默认只读。

## 5. Current-only 与稳定路径

- 当前规则和数据 Owner 使用固定路径原位更新。
- 不新增 `*_CURRENT_2`、`FINAL_v2`、`最终版3`、`最新版`。
- frontmatter 中可以维护 `version`，但版本号不进入 canonical 文件名。
- Git history 是普通版本演变的默认历史。
- 只有独立决策价值的旧工作件才进入 Archive。

### Gate 例外

Gate 是事件证据。例如 `GEO-1_通过记录.md` 记录一次已经发生的通过事实，不应随着 GEO-2 推进被重命名成新的 Current。

后续 Gate 使用稳定的 Gate ID，例如：

```text
GEO-2_通过记录.md
VIS-1_通过记录.md
GEO-3_通过记录.md
TXT-1_通过记录.md
```

如果同一 Gate 曾失败后重审，需要保存过程时，可在 Gate 子目录中使用明确事件名 / 日期，而不是 `CURRENT`。

## 6. 历史真实性与美术边界

- 图像生成模型没有重新决定城市、关隘、河流、山脉位置的权限。
- 历史坐标、区域锚与自然地理控制优先于美术构图。
- 资料不足时保留 `ANCHORED / ANCHORED-REGION / PROVISIONAL / PERIOD-SENSITIVE` 等不确定性，不伪造精度。
- 正式地图文字必须由真实字体 / 可编辑文字层生成；AI 伪汉字不进入正式资产。
- 动态势力、军队、玩家位置、任务状态等 Runtime 信息不永久烘焙进中立基础地图。

## 7. AI 角色分离

如果当前 AI 被指定为**技术设计 / 架构 / 审核角色**，则必须遵守：

- 可以读取资料、设计规范、维护数据、写 Prompt、审核外部图像、判 Gate、写回仓库；
- 不直接生成或编辑项目地图图片；
- 不因具备图像生成能力而跳过外部图像执行器；
- 生图 / 修图交给 Owner 指定的图像执行 AI（例如 KIMI）；
- 外部执行器不得自行 supersede Rule / Data Owner。

详细职责见 `00_当前规范/制图生产经验与AI协作规范.md`。

## 8. Legacy 引用处理

2026-08-27 之前的正文可能仍以旧 `_CURRENT` 文件名描述依赖。处理规则：

1. 先查 `README.md` 的迁移映射；
2. 以当前 canonical 路径为准；
3. 不因为正文出现旧名称而重新创建旧路径；
4. 当某文档因真实内容变化被正式修改时，同时把该文档内涉及到的旧依赖名更新为 canonical 路径；
5. 不为纯粹清理历史措辞而批量改写所有正文，避免制造无意义 diff。

## 9. 新地图扩展规则

未来新增 Level 2 区域图或 Level 3 专题图时，不要把所有文档继续堆到 `游戏地图/` 根层。

优先按对象形成深度目录，例如：

```text
01_制图数据/区域图/<区域>/...
02_考据与审核/Gates/<地图或阶段>/...
03_产出/区域图/<区域>/...
```

只有跨所有地图长期生效的原则才升级到 `00_当前规范/游戏地图美术核心规范.md` 或 `制图生产经验与AI协作规范.md`。

## 10. Final Check

正式写回前至少检查：

- 是否修改了唯一 Owner；
- 是否制造了第二份事实源；
- 是否把 Evidence 错当 Current；
- 是否误读 Archive；
- 是否需要传播到对象清单 / Gate / 历史核验；
- 是否出现新的 `_CURRENT` / `FINAL_v2` 类路径；
- 图片是否进入 `03_产出/` 而不是规则目录；
- 当前 HEAD 是否仍是本次工作的 Base；
- 当前 AI 如果是技术设计 / 审核角色，是否错误承担了生图工作。
