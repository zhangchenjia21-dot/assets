# 通用资产库｜维护规范 v0.8

> 目标是稳定、可复用、事实归属清晰、可被 Runtime 有界消费；不是追求资产数量、文件数量或 Prompt 规则数量。

## 1. 分类 / Core-first

新机制先分类 Core / Gameplay-Framework / Theme / World-specific。多个消费者需要同一长期事实：先 Shared Foundation + Canonical Owner，再做下游 / 世界专用资产。

当前新增稳定 Shared Foundation Reference：

- `EP-KINSHIP-CORE v0.1`；
- `EP-POLITICS-CORE v0.1`。

## 2. Canonical Owner / Relations

每类长期事实一个 Owner。正式关系区分 Hard / Optional / Conditional / Provider→Consumer / Handoff / Contribution / Reference。

```text
Dependency Graph != Context Inclusion Graph
Hard Dependency != Transitive Prompt Inclusion
```

Politics Reference：

```text
ORG Role Holding != Politics Public Authority
Kinship Fact != Political Succession Outcome
Reputation != Political Recognition
War Occupation != Political Control
```

## 3. Generic Identity

`first consumer != generic owner`。

汉末三国是 Politics 的首个迁移消费者，不是 `EP-POLITICS-CORE` 的身份来源。Generic Core 不保留汉末专名、州郡官制、称帝流程或固定“势力 / 政务”Surface。

## 4. Runtime Context Contract

Pattern：`[[通用资产库_RuntimeContextContract模式_v0.6]]`；Index：`[[通用资产库_RuntimeContextContract索引_v0.6]]`。

每个新 Core / 重要 Expansion 至少回答 19 项 Context Contract；当前不冻结统一 token budget。

## 5. Large Registry + Large Relation Graph

### Definition Registry

```text
Domain Active != Full Definition Registry Visible
```

### Relation Graph

Kinship + Politics 已把大型图规则提升为通用 Pattern：

```text
Large Relation Graph
→ persist semantically primary canonical relations
→ Program deterministic current-relevant path / subgraph selection
→ owner-safe + player-safe bounded projection
→ Model only for open semantic work
```

```text
Whole Relation Graph != Model Prompt
Derived Pairwise Projection != Canonical Truth
```

不要机械理解成“所有关系都只能存源边”。Membership、Recognition、Agreement、Shared Bond 等如果本身就是 Canonical Truth，就应持久化。禁止的是为查询便利把**可确定重算的派生 pairwise / aggregate 关系**大规模镜像成第二事实源。

## 6. Definition / Materialization

```text
Source Asset
→ Game-local Canonical Asset / Definition
→ Runtime State
```

具体可交互人物 / 家族 / 政权 / 政治议题必须有稳定引用；未知亲属位置、未成立的建国口号、一次性政治表达可以暂不 materialize 为 durable object。

## 7. Background / Feature-Module / Join

继续遵守：

```text
Background deterministic progression != Model Activation
Package Included != Feature Enabled != Module Enabled != Runtime Relevant != Model Visible
```

多 Owner 协作使用 bounded projection join；后续能力在正式上游 Outcome / Trigger 成立后再激活。

## 8. Sidecar / Born-compliant

成熟旧资产可在业务语义不变时使用唯一 Sidecar；新 Core 默认正文内建 Context Contract。

Kinship / Politics 的正文最初按 v0.5 born-compliant，并已经实际满足 v0.6 新增 graph rule；Index v0.6 记录兼容 PASS，不为相同 asset version 创建第二 Sidecar。

## 9. Audit Cadence

```text
Asset Audit
→ Boundary Cluster
→ Architecture Reflection / Future Explosion
→ Shared Foundation Cluster
→ Family / Library Convergence
```

已完成：

- Kinship 单资产 + boundary cluster；
- Politics 单资产 + boundary cluster；
- Kinship + Politics Shared Foundation Architecture Reflection；
- Large Relation Graph rule promotion。

下一正式收敛点：汉末 Politics migration 完成后做 real-consumer convergence；Economy / War 完成后做 Shared Foundation Convergence。

## 10. Migration Discipline

新 Generic Core 吸收旧 World-specific composite owner 时，必须先做 Ledger：

```text
DELETE / MERGE / MIGRATE / RENAME / SPLIT / KEEP AS REFERENCE / REBIND
```

Politics Han Migration 已规划：

- Faction → ORG / Politics split；
- Affiliation → ORG + issue stance；
- Office → ORG；
- Public Authority / Recognition / Claim / Control → Politics；
- Succession → Kinship + ORG + Politics (+ future Law)。

不得在一次迁移中顺手吞并尚未建立的 Economy / War / Law Owner。

## 11. Active-only / Archive

同一维护文档族 active 只保留 current；superseded 版本进入 `通用资产库/99_归档/版本历史/`。

人类治理文档采用一位小版本；Canonical Asset 已有语义版本不为纯治理变化机械 bump。

## 12. Repository Sync

正式写回前执行 Pre-push Freshness；new current 先存在，再归档旧 current；写后 readback。同轮 >=3 正式文件生成 Transport ZIP + manifest。
