# 通用资产库｜维护规范 v0.5

> [!summary]
> 目标不是让通用库越来越大，而是让它成为**稳定、可复用、Canonical Ownership 清晰，并且在大型组合下仍能被 Runtime 有界消费的机制资产层**。

---

# 1. 新资产先分类

任何新想法先判断：

- **Core**：拥有跨世界长期 Canonical Domain；
- **Gameplay / Framework**：在已有 Core 上形成可复用玩法闭环；
- **Theme**：依赖已有 Core，对某领域做增量语义深化；
- **World-specific**：离不开具体时代 / 地理 / 组织 / 历史事实，不进入通用库。

无法说明独立 Owner 的机制，优先作为 Contribution / Theme / Module。

---

# 2. Core-first / Shared Foundation

当多个 World-specific / Theme Consumer 需要同一底层机制时：

```text
Domain Survey
↓
Genericity / Shared Foundation
↓
Canonical Owner
↓
Generic Core
↓
Downstream / Theme
↓
World-specific Consumer
```

禁止先让多个消费者各自拥有临时事实源，最后再大规模抽 Core。

---

# 3. Canonical Owner / Authority

每类长期事实只有一个 Canonical Owner。

必须区分：

- Definition Contributor；
- Instance State Owner；
- Derived Projection；
- Reference / Read Model；
- Cache；
- UI Contributor。

Projection / cache 默认不可反写 Authoritative State。

Aggregate State 与 Named Instance State 必须有 bridge，避免双计数。

---

# 4. 关系必须类型化

正式关系：

- Hard Dependency；
- Optional Integration；
- Feature / Module Conditional Dependency；
- Provider → Consumer；
- Handoff；
- Contribution；
- Reference / Read-only。

禁止模糊 `dependency`、Hard Cycle 和 fallback second owner。

正式冻结：

> **Dependency Graph != Context Inclusion Graph。**

依赖表示语义 / 权威 /组合关系，不代表模型上下文必须全文包含上游。

---

# 5. World Consumer 不反向污染 Generic Asset

首发世界可以提供：

- reference consumer；
- world-specific example；
- compatibility note。

不能把世界专名、历史人物、神名、地理、专用组织写进 Generic Core Canonical Mechanism。

`first consumer != generic owner`。


## 5.1 Authoring Provenance != Current Governance Binding

成熟旧资产正文中的历史 `skill` / `blueprint` 字段可以记录创作时 provenance。

如果：

- Canonical Domain Semantics 未变；
- Generic Identity 已经成立；
- current Matrix / Blueprint / Maintenance / Context Index 已明确当前 binding；

则纯粹的旧 provenance 不强迫业务正文 Patch。

禁止反过来把历史 `blueprint v0.x` 解释为当前治理必须回退到旧版本。

只有 provenance 字段会改变实际消费 / Owner /依赖时，才要求正文修订。

---

# 6. Runtime Context Contract｜新增强制维护规则

所有新 Core / 重要 Expansion 从本版本起必须遵守：

```text
Asset Library
!= Game Enabled Asset Set
!= Current Runtime Relevant Set
!= Current Model Visible Working Set
```

以及：

```text
Full Semantic Asset != Model Prompt Payload
```

Context Contract 采用：

> `[[通用资产库_RuntimeContextContract模式_v0.4]]`

至少回答：

1. Routing Profile；
2. Immediate Activation；
3. State-mandatory Activation（如适用）；
4. Downstream Activation；
5. No-load Conditions；
6. Minimal Read Set；
7. Model-needed Semantics；
8. Program-owned Logic［
9. Output Candidate；
10. Handoff / Information Boundary；
11. Context Cost / Bounded Strategy；
12. Feature / Module Activation Hierarchy（如适用）；
13. Background Program Progression（如适用）；
14. Definition Registry / Library Projection（如适用）；
15. Bounded Sufficiency / Context Completeness ;
 16. Narrative Affordance / Runtime Referent（如适用）。

当前不冻结统一 token budget。

---

# 7. Model-first Semantic Routing

推荐方向：

```text
Player Input
+
Enabled Routing Profiles
+
minimal current scene / active context
↓
Router Model
↓
immediate Domain / Intent candidates
↓
Program structural validation
+
state-mandatory augmentation
↓
JIT bounded projection
```

Program 不重复自然语言语义 Router，只做结构合法性与 authoritative state 约束。

Router 不负责预测全部后果；后续通过 Formal Event / Typed Handoff 再激活。

Router miss 不得成为 Open Attempt 白名单。

---

# 7A. Background Progression / Feature-Module Gate

长期 Need / timer / cooldown / routine automation 若可 deterministic 推进，例如：

- Need accumulation；
- timer / cooldown［
- routine automation［
- deterministic resource consumption；
- threshold bookkeeping；

则：

```text
Background Runtime Progression
!= Model Activation
```

只有当前输入需要语义理解、出现玩家决策 / warning /开放式解释，或正式 Handoff 进入另一个 Domain 时，才按需构建 Model Working Set。

## 7.B Feature / Module Activation Hierarchy

带 Feature / Module 的 Package 必须区分：

```text
Package Included != Feature Enabled != Module Enabled != Runtime Relevant != Model Visible
```

关闭 Feature / Module 不进入 Router Directory，不产生 Conditional Dependency，不显示其条件 Surface；已启用但当前无关的 Module 也不自动进入 Model Working Set。

大型 Definition Registry 进一步冻结：

```text
Domain Active != Full Definition Registry Visible
```

Spell / Invocation / Ability Catalog 应通过 actor-accessible / authorized subset + intent-relevant retrieval 得到少量 selected Definition Projection。

并冻结：

```text
Bounded != Starved
```

Minimal Read 必须“最小充分”，不能为了省 token 把当前模型职责所需的角色、Definition、目标、关键历史或世界边界裁掉。

---

# 8. Program Authority

资产 / 模型不得拥有：

- RNG / Dice；
- Program Judge［
- Formal Outcome；
- direct State Mutation；
- Atomic Commit［
- Save / Restore authority。

可 deterministic、安全、可测试的规则优先留在 Program，不为了“文档里写了规则”就放进模型 Working Set。

---

# 9. Information Boundary

后台 Truth != Player Knowledge != NPC Knowledge != Narrative Context。

每个 Context Contract 必须说明：

- 哪些 Authoritative State 可被当前模型职责读取；
- 哪些只能形成 player-safe / npc-safe projection［
- 哪些 source history 只能摘要而不能全量注入。

---

# 10. UI Surface

新资产默认优先贡献：

```text
Core Surface Contribution
→ Entity Detail
→ Player Status / Detail
→ Contextual
→ Global Notice
→ Extension Surface
```

一级 Extension Surface 只在形成长期独立工作空间时 owns；Owner 唯一。

---

# 11. Version Discipline

## Patch

适用于：

- stale ref / metadata［
- dependency closure［
- UI / Host wording；
- Runtime Context Contract retrofit；
- 不改变 Canonical Owner 的接口补齐。

## Minor

新增重要机制 /状态 /合法状态，但 Owner 不变。

## Major / Major Rewrite

Owner / Scope / topology 真正改变。

Major Rewrite 必须：supersedes + migration + consumer audit + blueprint / matrix 同步。

---

# 12. Asset / Cluster / Library Audit

## Asset Audit

单资产完成即执行。

## Cluster Audit

2–5 个高耦合资产形成簇后执行，重点检查：

- duplicate owner［
- semantic namespace［
- dependency cycle；
- state mirroring；
- pairwise integration explosion；
- transitive context explosion；
- Surface conflict［
- Context Contract 组合行为。

## Generic Library Convergence

触发：

- 新增 P0 Core［
- Core 拆合；
- World-specific 提升 Generic；
- 依赖 / Surface / Owner 冲突；
- Context Architecture 变化；
- G9 vNext / Creator 绑定。


```text

```

# 14A. Context Sidecar Governance｜Retrofit 新规则

成熟旧资产如果 Context Audit 证明 Domain Semantics / Owner / Dependency / Handoff 均不需要改变，允许用唯一 Runtime Context Contract Sidecar 补齐横切绑定元数据。

Sidecar：

- 不属于第二份 Expansion 正文［
- `canonical_domain_ownership: none`；
- 必须绑定精确 asset_id + asset_version；
- 不能新增原资产没有的 gameplay semantics［
- 不能覆盖 Canonical Asset Domain Semantics［
- 同一 asset_id + version 只能有一个 current Contract source。

若 Context Audit 暴露真实语义缺陷，必须回资产正文 Patch / Minor / Major，不能用 Sidecar 掩盖。

Canonical location 统一登记：`[[通用资产库_RuntimeContextContract索引_v0.3]]`。

# 15. Periodic Architecture Audit / User Reflection

至少在：

- 新 Shared Foundation Core 形成；
- 高耦合 Cluster 形成；
- 大迁移 / Schema Freeze 前［
- Stage Closure 前；
- 项目所有者主动质疑长期方向时；

执行 Future Explosion Review。

重点问：规模扩大 5–10 倍后是否有 linear / quadratic / combinatorial explosion、dual truth、context growth、shotgun change、过度平台化或成本恶化。

若涉及产品体验、长期维护偏好、成本与不可逆架构，Agent 先给事实 /风险 /推荐，再邀请用户做 Owner Reflection。

# 19. 最终维护原则

> **先维护 Canonical Mechanism，再让世界消费；先保证 Runtime 可以局部激活，再允许资产生态继续扩张。世界可以越来越复杂，但模型不应因此每 Turn 重读整个世界。**
