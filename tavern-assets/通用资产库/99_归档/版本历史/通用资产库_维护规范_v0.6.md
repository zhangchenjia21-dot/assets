# 通用资产库｜维护规范 v0.6

> 目标是稳定、可复用、Owner 清晰、可被 Runtime 有界消费；不是追求资产数量、文件数量或 Prompt 规则数量。

## 1. 分类 / Core-first

新机制先分类 Core / Gameplay-Framework / Theme / World-specific。多个消费者需要同一长期事实：先 Shared Foundation + Canonical Owner，再做 Downstream / World-specific Consumer。

## 2. Canonical Owner / Relations

每类长期事实一个 Owner。区分 Definition Contributor / Runtime State Owner / Projection / Reference / UI Contributor。

正式关系：Hard / Optional / Feature-Module Conditional / Provider→Consumer / Handoff / Contribution / Reference。

```text
Dependency Graph != Context Inclusion Graph
Hard Dependency != Transitive Prompt Inclusion
```

## 3. Generic Identity

`first consumer != generic owner`。世界专名、历史事实、具体组织只作为 reference consumer / example / contribution。

成熟旧正文中的 stale `skill / blueprint` 可作为 authoring provenance；current binding 由 active Matrix / Blueprint / Maintenance / Context Index / current Skill 决定。

## 4. Runtime Context Contract

Pattern：`[[通用资产库_RuntimeContextContract模式_v0.5]]`。

每个新 Core /重要 Expansion 至少回答 18 项：Routing Profile；Immediate；State-mandatory；Downstream；No-load；Minimal Read；Model-needed；Program-owned；Output Candidate；Handoff/Information Boundary；Context Cost；Feature/Module Hierarchy；Background Progression；Registry Projection；Bounded Sufficiency；Narrative Referent；Cross-Owner Projection Join；Outcome-Gated Continuation。

当前不冻结统一 token budget。

## 5. Composite / Theme Context Join

```text
current purpose
→ ask each relevant Owner for bounded projection
→ preserve owner/provenance
→ join only current-needed facts
```

禁止递归展开 Provider 全文和 transitive dependencies；禁止 Consumer 建第二套 mirror state。

## 6. Outcome-Gated Continuation

```text
Potential downstream capability
!= Current Relevant downstream context
```

Cross-Action Coupling / Reaction / Counter / multi-stage resolution 必须先得到 authoritative upstream Outcome / Trigger，再加载 continuation 所需 Owner / Definition projection。

## 7. Definition / Materialization

```text
Source Asset
→ Game-local Canonical Asset / Definition
→ Runtime State / Effect Instance
```

Source Definition 不被 Runtime 反写。durable/interactable player-visible object 必须有 concrete authoritative ref；generic placeholder 不能冒充 semantic materialization。

## 8. Background / Feature-Module

```text
Background deterministic progression != Model Activation
Package Included != Feature Enabled != Module Enabled != Runtime Relevant != Model Visible
```

关闭能力不进入 Router Directory，也不产生 conditional dependency。

## 9. Registry / Bounded Sufficiency

```text
Domain Active != Full Definition Registry Visible
```

Registry → actor-accessible subset → intent retrieval → selected Definition projection。`Bounded != Starved`。

## 10. Sidecar

成熟 audited-current 资产若业务语义完全不变，只缺横切 Context Binding，允许唯一 Sidecar：precise bind `asset_id + version`；`canonical_domain_ownership: none`；不新增玩法；不修改 Outcome / Owner。

## 11. Audit Cadence

Asset Audit → Cluster → Wave / Library Convergence → Shared Foundation Cluster → Family Convergence。

Future Explosion 必查 context explosion、state mirroring、pairwise special-case、registry expansion、starvation、phantom referent、transitive prompt expansion、premature downstream loading。

## 12. Active-only / Archive

同一维护文档族 active 只保留 current；superseded 版本进入：`通用资产库/99_归档/版本历史/`。`90_审核/` 保留历史审核证据，因为它们不是 current 竞争者。

人类治理文档版本采用一位小版本：`v0.8 → v0.9 → v1.0 → v1.1`，不生成 `v0.10 / v0.11`。Canonical Asset 已有三段语义版本如 `v0.2.1` 不因本规则机械重编号。

## 13. Repository Sync

正式写回前执行 Pre-push Freshness；new current 先存在，再归档旧 current；写后 readback。同轮 >=3 正式文件生成 Transport ZIP + manifest。
