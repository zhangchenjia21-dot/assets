# 通用资产库｜维护规范 v0.7

> 目标是稳定、可复用、事实归属清晰、可被 Runtime 有界消费；不是追求资产数量、文件数量或 Prompt 规则数量。

## 1. 分类 / Core-first

新机制先分类 Core / Gameplay-Framework / Theme / World-specific。多个消费者需要同一长期事实：先 Shared Foundation + Canonical Owner，再做下游 /世界专用资产。

当前已验证新的 Shared Foundation Reference：`EP-KINSHIP-CORE v0.1`。

## 2. Canonical Owner / Relations

每类长期事实一个 Owner。正式关系区分 Hard / Optional / Conditional / Provider→Consumer / Handoff / Contribution / Reference。

```text
Dependency Graph != Context Inclusion Graph
Hard Dependency != Transitive Prompt Inclusion
```

## 3. Generic Identity

`first consumer != generic owner`。世界文化可以解释亲缘、家系、宗族、House、王室，但不能反向改变 Generic Kinship Owner。

## 4. Runtime Context Contract

Pattern：`[[通用资产库_RuntimeContextContract模式_v0.5]]`；Index：`[[通用资产库_RuntimeContextContract索引_v0.5]]`。

每个新 Core /重要 Expansion 至少回答 18 项 Context Contract；当前不冻结统一 token budget。

## 5. 大型图 / 大型 Registry

除大型 Definition Registry 外，长期增长的关系图同样必须有界消费。

Kinship Reference：

```text
Whole Graph
→ deterministic query / relevant subgraph
→ player-safe bounded projection
→ Model only for semantic work
```

优先保存产生结构的源事实，不为所有 pairwise 派生关系制造第二套持久状态。

此规则目前以 Kinship 为领域 Reference；是否升级为跨资产通用 Pattern，等待 Politics / Knowledge 等第二个图领域验证，不机械 bump Skill。

## 6. Definition / Materialization

```text
Source Asset
→ Game-local Canonical Asset / Definition
→ Runtime State
```

具体可交互人物 /家族对象必须有稳定引用；未知亲属位置可以暂不 materialize 为具体 NPC。

## 7. Background / Feature-Module / Join

继续遵守：

```text
Background deterministic progression != Model Activation
Package Included != Feature Enabled != Module Enabled != Runtime Relevant != Model Visible
```

多 Owner 协作使用 bounded projection join；后续能力在正式上游 Outcome / Trigger 成立后再激活。

## 8. Sidecar / Born-compliant

成熟旧资产可在业务语义不变时使用唯一 Sidecar；新 Core 默认正文内建 Context Contract。

Kinship v0.1 是 born-compliant Reference。

## 9. Audit Cadence

Asset Audit → Boundary Cluster → Shared Foundation Cluster → Family / Library Convergence。

Kinship 已完成单资产审核与 Relationship / ORG / Reputation 边界 Cluster。

下一高价值反思点：`Kinship + Politics` 完成后。

## 10. Active-only / Archive

同一维护文档族 active 只保留 current；superseded 版本进入 `通用资产库/99_归档/版本历史/`。

人类治理文档采用一位小版本；Canonical Asset 的已有三段语义版本不机械重编号。

## 11. Repository Sync

正式写回前执行 Pre-push Freshness；new current 先存在，再归档旧 current；写后 readback。同轮 >=3 正式文件生成 Transport ZIP + manifest。
